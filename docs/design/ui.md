# M0 interface

> Status: Draft · Built in [M0.3 to M0.5](../milestones/m0.md#work-packages) · Rules: [visual style](./visual-style.md), [UX guidelines](./ux-guidelines.md) · Visual language: [design system](./design-system.md) · Libraries: [UI stack](../../CONTRIBUTING.md#ui-stack)

This document designs every screen M0 ships. It applies the [core philosophy](../../AGENTS.md#core-philosophy-beauty-is-productivity-颜值也是生产力): the agent's work should be legible at a glance, every state is designed, and nothing moves without a reason. Colors, sizes, radii and timings come from the [design system](./design-system.md); this document says where they are used.

## Window and chrome

- **macOS**: hidden title bar, traffic lights at `{ x: 16, y: 14 }`, centred in a 40 px top bar. The top bar leaves 80 px on the left for them. The [zoom](#zoom) scales the top bar but not the traffic lights, so main moves them to `x = 16 × zoom` and `y = (40 × zoom − 12) / 2`, rounded, which keeps them centred, and the renderer leaves them their unzoomed 52 px as `--traffic-lights` (`52px / var(--zoom)`).
- **Windows and Linux**: hidden title bar with `titleBarOverlay` window controls, 40 px high times the zoom, so they fill the zoomed top bar, colored from the current theme and updated with `setTitleBarOverlay` when the theme changes: the background is `--bg-app`, the symbols `--text-primary` (`#262626` light, `#ECECEA` dark). The top bar keeps clear of the controls with `env(titlebar-area-x)` and `env(titlebar-area-width)`. There is no menu bar; the renderer handles the shortcuts.
- The top bar is the drag region (`app-region-drag`). Everything clickable inside it is `app-region-no-drag`.
- The window remembers its size, position and maximized state, and never reopens off-screen ([persistence](./persistence.md#window-and-app-state)). Minimum size: 960 × 600.
- The window's own background follows the effective theme, `#FFFFFF` light and `#1B1B1A` dark, the values of `--bg-app`, also when the theme changes while it is open.
- On Windows and Linux, closing the last window quits the app, so it goes through the quit confirmation first; on macOS it only closes the window, and agents and terminals keep running.

### Zoom

- The whole window zooms with Chromium's page zoom, in Chrome's steps of 80, 90, 100, 110, 125 and 150%, and opens at 100%, where its frame matches the reference's ([problem 62](../milestones/m0-feedback.md#62-the-interface-reads-small-and-cannot-be-zoomed)). The [keyboard](#keyboard) and, on macOS, the View menu change it.
- The level is `appearance.zoom` in [settings](./persistence.md#settings), and the renderer sets it on `<html>` as `--zoom`. Main sets it on every load of a window (`did-navigate`), where it applies before the page's first script; `webPreferences.zoomFactor` would come back on a reload after the user chose 100%.
- Sizes in the [design system](./design-system.md) are CSS pixels at 100%.

## Launch

Launching should feel like opening a lid, not waiting for a page: no white or black flash, no empty window, and no content jumping into place.

| Moment                 | What is on screen                                                                                                                                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Before the first frame | Nothing. Main reads the settings, then creates the window hidden, with `backgroundColor` set to `--background` of the theme from settings (`nativeTheme` decides for System), and shows it on `ready-to-show` |
| First frame            | The app shell from the renderer bundle alone: window controls, the sidebar on surface 0 with `Skeleton` rows at the real 28 px row height, and the empty main surface                                         |
| Data arrives           | Projects and sessions from the agent host replace the skeleton rows in place, fading in over `--duration-base`; nothing moves, because the rows already had their size                                        |
| A session is restored  | With **Restore the last session**, the main area shows the thread skeleton until the snapshot arrives, then the thread fades in                                                                               |
| Nothing to restore     | [New session](#new-session) in the project chosen last, or with none chosen while there are no projects                                                                                                       |

- The first frame needs no data and no agent host, so it is on screen within the [launch budget](../milestones/m0.md#performance-budgets) (500 ms to the first interactive frame) whatever the host is doing.
- A launch that takes longer than 1 s, such as a cold start after an update, shows "Starting OverBench…" with a `Spinner` centred in the main area, so a slow start never looks frozen; a normal start never shows it.
- There is no splash screen. A launch mark comes once the OverBench logo is final, and it follows the same rule: it appears only when the launch is slow, so it never delays a fast one.
- With reduce-motion on, the content appears without fading.

## Layout

```text
┌─────────────┬──────────────────────────────────────────┬──────────────────────────┐
│ ● ● ●     ◫ │ ✳ Fix flaky login ⌄             ⎇ fix ▣ │ ▣ zsh  ▣ pnpm ●  +   ⤢ × │  top bar · side panel header
├─────────────┤                                          │ ~/overbench $ pnpm test  │
│ ✎ New       │   ┌──────────────────────────────────┐   │  ✓ 42 passed             │
│ overbench + │   │ The login test fails on CI …     │   │  ✗ 1 failed              │  terminal
│  ✳ Fix fl 2 │   └──────────────────────────────────┘   │ ~/overbench $ █          │
│  ✳ Fix fla  │ I'll start by reading the test and …     │                          │  agent
│   ◇ Explore │ Edited session.ts +4 −3 ›                │                          │  work, folded
│  ◎ Add da ↳1│                                          │                          │
│  ✳ Bump d ⊙ │ ⊙ Committed 3f2a1c1 fix(auth): read …    │                          │  git event
│ website › + │ ┌─────────────────────────────────────┐  │                          │
│             │ │ Ask Claude Code to…               ↑ │  │                          │  composer
│             │ └─────────────────────────────────────┘  │                          │
│ ⚙ Settings  │   Default ⌄          Opus 5.5 High ⌄ ◔   │                          │  control row
└─────────────┴──────────────────────────────────────────┴──────────────────────────┘
```

- Built with `ResizablePanelGroup`. The sidebar defaults to 260 px, resizes between 200 and 400 px, collapses with `Mod+B` through the panel's own collapse, sliding as the design system's [sidebar slide](./design-system.md#patterns) describes, and remembers its size per device. The width at collapse is saved too, so an app that starts collapsed expands back to it, not to the minimum. Collapsed, the handle takes no width, so no line shows at the window's edge.
- The sidebar sits on surface 0 and the thread on surface 1. The step and the handle's hairline separate them; hovering or dragging the handle shows its [grip](./design-system.md#one-line-per-surface).
- The thread is a single centred column of 50em of prose plus its 24 px gutters (`max-w-thread`, 798 px at the default 15 px), about 50 Chinese characters a line, so prose keeps a comfortable line length at any window width. Tool calls, diffs and the composer below use the same column, so the composer's edges line up with the prose. Where scrollbars take room (Windows, and macOS set to show them), the thread's scroller keeps a gutter for its scrollbar on the right and the column centres in what is left; the composer's row leaves the same width, measured from the scroller, so the edges still meet.
- The **side panel** on the right of the main area holds one pane at a time: the [terminal](#terminal), the [files](#files) or, opened from the thread, an [artifact](./artifacts.md#opening-from-a-session). It sits flush on surface 0, like the sidebar on the left, so the thread on surface 1 is framed by two quieter surfaces, each meeting it at a soft hairline ([one line per surface](./design-system.md#one-line-per-surface)). The layout follows the reference; the styling is OverBench's own. The thread column keeps the rest of the width and its own top bar. Each pane has a toggle at the right end of the top bar, as the reference's row of pane buttons: **Files** (`Folder`) and **Terminal** (`SquareTerminal`); the open pane's toggle is [pressed](./design-system.md#toggle-buttons). An artifact's pane has no toggle, since it opens from the thread. A toggle shows its pane, or closes the panel when its pane is shown, and the open pane is remembered per project, except an artifact's. Each pane keeps its own width (the terminal 340 px by default, the files and an artifact 560 px). The Changes panel arrives later as a third pane.

## Screens

### New session

> Decided while the maintainer was away (2026-10-22); to be reviewed. The maintainer chose the direction on the design canvas, page "合并选择": C's composer as the base, one control for the agent and the model, each agent's plan usage in that control, and the project and branch inside the composer under a heading that names no project. The details below that the canvas left open were settled in implementation.

Opened by **New session** (`Mod+N`, also in the File menu) and by the **+** on a project's row in the sidebar, which opens it in that project, and by **New sub-session** in a session's menus, which opens it [for a sub-session](#for-a-sub-session) of that session. It is also what the main area shows when nothing else is, with the default agent chosen: at [launch](#launch) with no session to reopen, the first run included; after a project is added with `Mod+O` or File › Open Project…, in that project; and when the shown session is closed or deleted, or goes away with its parent, in that session's project, or with No project for a session started without one. There is no welcome screen: this one is the first screen too. OverBench drives several agents, so this screen is its own rather than Claude Desktop's or Codex's: where to work, which agent and model, and how much of each agent's plan is left are all chosen in one place, in the composer.

```text
                         What should we work on?
 ┌────────────────────────────────────────────────────────────────┐
 │ Ask Claude Code to…                                            │
 │                                                                │
 │                                                              ↑ │
 └────────────────────────────────────────────────────────────────┘
  ▢ overbench / ⎇ main            ✳ Claude Code  Opus 5.5  High ⌄  Default ⌄   route line

  Recent
  ✳ Fix the flaky login test                       overbench    2h
  ◎ Map the project structure                      self-media   1d
```

- **Layout**: the top bar names nothing and draws no line under it, as in the reference's start screen, where the heading says where you are; it holds the chosen project's git status and pane toggles. Below it, the heading, the composer and **Recent** form one block in the thread's column (`max-w-thread`, so a 750 px composer at the default 15 px), centred in the area and raised 28 px above true centre, as in the reference's start screen, so the eye lands on the composer. The reference's start screen is narrower, about 680 px; OverBench keeps the session's width, so the composer does not widen once the first message is sent (decided on 2026-10-23 for [#125](https://github.com/overbench/overbench/issues/125)). The block grows with the draft and stays centred.
- **Heading**: "What should we work on?", in the serif greeting step in `--foreground`, centred, as the reference greets in a serif ([type scale](./design-system.md#type-scale)). It names no project and no agent, because both are chosen below it.
- **Composer**: the session's composer, taller on this screen: its text area is 112 px high empty, the reference's start composer, with Send in its lower right corner. Under the box sits the **route line**, a `--control-height` row that reads left to right as where and with what the session starts: on the left the project and the branch, on the right the agent and model and the mode, as the reference puts its project picker and model under its start composer ([#127](https://github.com/overbench/overbench/issues/127), 2026-10-23). The parts are `quiet` `compact` buttons in `--muted-foreground`, joined by a `/` in `--muted-foreground`; the agent's name and the project's name are `--foreground`, and their text lines up with the composer's. The text area and the send button follow as in the session. The placeholder is "Ask <agent> to…", or "Describe a task…" while no agent is chosen.
- **What gives way** on a narrow window: the branch first, down to its icon, then the project's name, then the model's name; the agent's name, the level and the mode keep their width, and every cut name shows in full in its tooltip.

The route line's parts:

- **Project**: `Folder` and the project's name, or "No project", or "Choose a project" while none is. It opens the project menu under it, after the reference's folder menu, a [search menu](./design-system.md#menus-and-dialogs): a search field ("Search projects…") over **No project**, which starts the session in a [scratch folder](./session-model.md#sessions-without-a-project) of its own, then after a separator **Recent**, the projects by name alone, most recently opened first, then after a separator **Open project…**, which adds a folder and chooses it. A project whose folder name another shares adds, in `--muted-foreground`, the fewest parent folders that tell them apart; a missing one is disabled with "Missing"; the full path is the row's tooltip. Typing filters the projects by name and those folders, leaving **Open project…** in place, with "No matching projects" when none match. Only the projects scroll. It starts at the selected project, or at the one whose **+** opened the screen. With no projects yet, as on the first run, it reads "Choose a project" and the menu holds only the search field, **No project** and **Open project…**.
- **Branch**: `GitBranch` and the branch the session starts on, in mono; the short commit id when `HEAD` is detached. It is shown, not chosen: OverBench has no branch switching yet, and the branch belongs to the repository, whose one place is the [git status](#git-in-the-top-bar) in the top bar, so this label opens nothing and says so in its tooltip ("The session starts on this branch"). It is left out, with its `/`, for No project and for a folder that is not a repository.
- **Agent and model**: the agent's mark and name, then the model's name and the reasoning level in `--text-secondary` ([model names](./design-system.md#model-names-and-reasoning-levels)), then `ChevronDown`. For a `provider/model` name only the model part shows. While its models are unknown, until the agent has first started, it shows the agent alone; while no agent is chosen (**Ask each time** in Settings), "Choose an agent". It opens the [agent menu](#agent-menu).
- **Mode**: the agent's mode option, named as the agent names it ("Default", "Accept edits"), with `ChevronDown`; its menu lists the modes and closes on a choice, as the session's mode menu does. It shows once the agent's options are known.

The states of the screen:

- **No project or no agent chosen**: Send is disabled, and its tooltip says what is missing ("Choose a project first", "Choose an agent first").
- **A missing project**: its name shows with "Missing" after it, and one line in `--destructive` under the route line says "This project's folder is missing. Choose another project."; Send is disabled.
- **No agent can start**: when every agent needs installing, as on a first run without Node.js, one line in `--destructive` under the route line says why, so it shows before the first session: "No agent can start yet: Claude Code and Codex need Node.js 22 or later." while some wait for Node.js, which installing it fixes, else "No agent can start yet. Install one to begin.". An `outline` `xs` **Set up agents…** follows it and opens Settings › Agents, where each agent's page says how it installs ([Settings › Agents](#settings--agents)). The line goes once one agent can start; the agent stays to be chosen in the [agent menu](#agent-menu). Decided with the maintainer on 2026-10-23.
- **A reached plan limit**: when the chosen agent's tightest window is used up, the placeholder says when it resets ("Codex's 5-hour limit resets in 1h 12m"), as the session's composer does; the draft can still be written and sent, and the agent answers for itself.
- **Recent**: under the composer, a group label over the three sessions you used last, in any project: each row shows the agent's mark, the title, the project's name and how long ago, in the [row anatomy](./visual-style.md#rows), and opens the session. Sub-sessions and subagents are left out. With no sessions yet the group is not shown.

The git status and the terminal toggle follow the chosen project. The chosen agent starts while the screen is shown, so a send waits for the session alone. The first send creates the session there and sends the message: the message shows at once as the first entry of the thread, with "Starting Claude Code…" ("Installing Claude Code…" while its adapter installs) and the latest output under it, and the session takes over once its thread is loaded, so no skeleton shows in between. The text leaves the [draft](./persistence.md#composer-drafts) with the request, so a window reloaded meanwhile does not offer it again, and comes back to it when the start fails, unless something else was written there meanwhile, so nothing is lost (**Back** returns here with the text); the message then goes with the session, so when the agent asks to sign in first the session opens with it in its thread and **Sign in…** above the composer, and signing in sends it. Opening the screen again while it is shown keeps the agent you chose.

#### For a sub-session

**New sub-session** opens the screen with the agent picked in its submenu, so a sub-session, too, is created only with its first message ([sub-sessions](./session-model.md#sub-sessions)).

- **The parent** leads the top bar as it leads a sub-session's: its title, a `quiet` button that opens it, then `ChevronRight` and "New sub-session" in place of "New session".
- **The project** in the route line is the parent's, shown and not chosen, with the tooltip "A sub-session works in its parent's project": `Folder` and the project's name, or "No project" for a parent started without one, whose scratch folder the sub-session shares. The branch, the agent and model and the mode work as on the screen for a session of its own, and the agent can still be changed there.
- **The first send** creates the session under the parent, which the sidebar then lists under it. Leaving the screen without sending, through the parent's link or anywhere else, creates nothing; the text stays in the screen's draft as it does for a session of its own.
- Opening New session again, with `Mod+N` or a project's **+**, makes it the screen for a session of its own, keeping the agent. So does the parent going away, where the parent ran.

#### Agent menu

```text
┌──────────────────────────────────────────────────────────────────┐
│ ⌕ Search agents and models                                       │
├─────────────────────────────┬────────────────────────────────────┤
│ ✳ Claude Code       ◔ 12%   │ Model                              │
│ ◎ Codex             ◕ 84%   │ Opus 5.5  Most capable           ✓ │
│ ▣ OpenCode        Sign in   │ Sonnet 5.5  Fast and capable       │
│                             │ Haiku 5.5  Fastest                 │
│                             │ ──────────────────────────────     │
│                             │ Reasoning                          │
│                             │ [ Low │ Medium │ High │ Max ]      │
│                             │ ──────────────────────────────     │
│                             │ Fast mode                      ( ) │
└─────────────────────────────┴────────────────────────────────────┘
```

One [search menu](./design-system.md#menus-and-dialogs) under the agent button, after T3 Code's model picker (a provider rail beside one searchable list, built on Base UI's `Combobox`) and Conductor's unified picker: the agents on the left, the shown agent's model menu on the right, and a search field across both. Choosing a model chooses its agent with it, so the agent and the model are one choice in one place ([one way in](./ux-guidelines.md#principles)), and no model waits for its agent to be chosen first.

- **Search**: "Search agents and models", focused while the menu is open. Typing turns the pane into the matching models of every agent, grouped under each agent's mark and name, and keeps in the rail only the agents with a match; a query that matches an agent's name lists all its models. The level and the switches step aside until the field is cleared, since they belong to one agent. The first match is highlighted, and `Enter` chooses it. With no match at all, the pane says "No matching agents or models". The menu keeps its size while it filters, so the rail and the pane do not jump.
- **The rail**: one row per agent, the installed ones first in catalog order, then those not installed, grouped by the same check as Settings › Agents, so a package agent whose adapter is not installed yet counts as not installed. A row is the mark, the name and, on the right, the agent's usage or what it needs:
  - With plan limits: a 12 px usage pie and the percentage of its tightest current window (`tightestLimit`, as the sidebar's usage chips), both in the window's [usage level](./design-system.md#usage-levels) (`usageTone`): `--text-tertiary` below 80% used, `--warning` from 80%, `--danger` from 95% or once the limit is reached. The tooltip lists every window with its percentage and the time to its reset. Opening the menu reads the limits again for the running agents that report them, as the usage popover does, which costs no model call beyond the title a long Claude Code report may bring ([reading the limits from `/usage`](./session-model.md#reading-the-limits-from-usage)).
  - Otherwise a word for what the agent needs: "Sign in", "Not installed", "Sets up on first use", "Installing…", "Failed". "Sets up on first use" is a package agent whose adapter is not installed yet while the user's own CLI is to run ([using the installed CLI](./agent-host.md#using-the-installed-cli)): its first start installs the adapter, and downloads the CLI too only if the adapter does not accept the user's version, which is known only once the adapter is installed. An agent that needs nothing and reports no limits shows nothing there.
  - The rail opens on the chosen agent, whose row takes the selected fill. It carries no check: the button already names it, and a check would push the usage out of line. A click or the arrow keys show another agent's pane without choosing that agent.
  - The rail scrolls once it holds more agents than fit. Adding agents from the ACP Registry will put a row at its foot; that row does not show until the feature is built.
- **The pane** lays out the shown agent's options as the session's [model menu](#composer) does: the models under the option's name, each with its description, then the reasoning level as segments, then the switches, with the values the session would [start with](./session-model.md#config-options). Choosing a model chooses the agent and the model and closes the menu. The level and the switches keep it open, and set what that agent starts with without choosing it. Only the chosen agent's model carries the check, so another agent's pane shows none. A long list scrolls by itself within 288 px, with scroll-edge fades, so the level and the switches stay in view.
  - An agent's models are known once it has started: ACP lists them only with a session, so the host reads them in a hidden session when New session first starts the agent ([config options](./session-model.md#config-options)), and keeps them. Before that the pane says "Claude Code lists its models once it has started." over **Use Claude Code**, which chooses the agent, and so starts it, and closes the menu. While New session's start of the agent runs, the `Skeleton` rows below stand in from 200 ms on, and from 1 s on "Starting Claude Code…" ("Installing Claude Code…" while its adapter installs) heads them, in the space kept for it. Once that start has finished without the models, because the read failed, the pane says "Claude Code lists its models after its first session. It starts with its default model, and you can change it in the session." instead.
  - An agent that needs to sign in says "Sign in to Claude Code to use it." with **Sign in…** above its models, and can still be chosen: the session then opens with the message in its thread and **Sign in…** above the composer. One not installed says "Claude Code is not installed." with **Install…**, and cannot be chosen. A package agent whose adapter is not installed yet says "Claude Code is not installed yet. It installs on first use.", or "Claude Code sets up on first use: OverBench installs its adapter, and downloads Claude Code too if the adapter does not accept the version of your claude." while the user's own CLI is to run, with **Install…**, and can still be chosen: its first session installs the adapter. One that failed shows its error with **Retry**. **Sign in…** and **Install…** open the agent's page in Settings › Agents, where both live.
  - While the agents' options load, and while the shown agent starts with none known yet, three `Skeleton` rows stand in at the rows' height, from 200 ms on.
- **Keyboard**: focus stays in the search field, where `↑` and `↓` move through the models and `Enter` chooses one, as in every [search menu](./design-system.md#menus-and-dialogs). `Tab` moves on to the rail, where `↑` and `↓` move between agents and show each one's pane, then to the segments and the switches. `Esc` closes the menu and focus returns to its button.
- **Size**: the rail fits its widest row; the pane is 320 px wide, as the session's model menu is. They share one menu surface, divided by a hairline ([two-pane menus](./design-system.md#menus-and-dialogs)).

What the session starts with is kept per agent and survives a restart: the agent's own defaults from its last new session, then the model, reasoning level and model options last chosen for it in any session, then what is set in this menu. The mode and the other options start at the agent's defaults in every new session, so a permissive mode chosen once is never carried into the next one ([session model](./session-model.md#config-options)).

### Session

The thread and the composer, described below. The top bar shows the agent's mark (14 px), the session title and a chevron button (`ChevronDown`, "More actions"). The mark names the agent, so its name is left out; a subagent's session leads with the `Bot` icon instead. The title's tooltip gives the full title and the agent. After the chevron, the [prompt cache](#prompt-cache) chip says how long the session's cache has left.

- **Renaming**: as in the reference, clicking the title renames the session in place. The title is a 25 px button with its text 4 px in and a 6 px radius, so its hover fill hugs the text as in the reference. A click turns it into a text field with its text selected, as tall as the text with no padding, a 1.5 px `--edit-ring` outline 1 px outside it and the selection in `--edit-selection`. The outline's outer edge is the button's box, and the button's keyboard focus ring is the same 1.5 px `--edit-ring` line inside its edge, so the hover fill, the field and the focus that returns after `Enter` or `Esc` all take one shape, and neither the text nor the menu's chevron moves. It starts at the title's width and grows with its text, the git status giving way first. `Enter` or leaving the field keeps the title, `Esc` cancels, and an empty title returns to the agent's ([titles](./session-model.md#titles)). The field stays until the host has the new title, so the old one never shows in between. If the rename fails, the field stays, marked invalid with the error as its tooltip; `Enter` tries again and leaving it gives up.
- **The menu**: the chevron opens **Rename**, which starts the same field, **New sub-session** (with a submenu of agents, each opening [New session](#for-a-sub-session) for a sub-session with that agent), **Close** and, after a separator, **Delete…** (in `--destructive`): the session's own items, one list shared with the sidebar row's context menu and **More** button, styled as in [menus](./design-system.md#menus-and-dialogs) ([session lifecycle](./session-model.md#session-lifecycle)). With the menu open the fill sits on the chevron alone. Closing or deleting the shown session, or its parent, leaves it for [New session](#new-session), and a closed session opens again from the sidebar with `session/load`.

A sub-session's top bar starts with its parent's title as a link. On the right of the top bar sit the [git status](#git-in-the-top-bar) and the terminal toggle.

### Subagent

Opening a subagent ([sub-sessions](./session-model.md#sub-sessions)) shows its own thread: the parent's instructions first, as a quoted `session_message` entry labelled with the parent's title, then the subagent's work, including its permission requests. The agent drives it, so in place of the composer a bar reads "Claude Code runs this subagent for Fix flaky login test", with **Stop** when the agent allows it and **Back to** the parent.

### Usage

The usage page, opened from the sidebar's **Usage** row, is designed in [usage statistics](./usage.md#interface): a dashboard of the agents' tokens for a chosen agent, time range and source, with the plan limits beside the trend. Its settings are Settings › Usage ([settings](./usage.md#settings)), the section after Agents.

- **Filter row on a narrow window**: the filters are two groups, what is counted (the agent, then the source) on the left and when (the range, then **Custom**) on the right. At the default window, 1280 px with the sidebar open, in English and Chinese, they share one line: an agent's segment is its mark alone, with its name in a tooltip and as its accessible name. On a narrower window the right group wraps under the left one, whole; only below the width of one group do its own controls wrap. Decided while the maintainer was away; to be reviewed.

### Artifacts

> Accepted for [issue #11](https://github.com/overbench/overbench/issues/11) on 2026-10-23; not built yet.

The pages agents hand the user through OverBench's [artifacts](../architecture.md#artifacts) service, designed in [artifacts](./artifacts.md#interface):

- **The Artifacts page**, opened from the sidebar's **Artifacts** row: every artifact as a card with a thumbnail, grouped by project, then by session, or grouped and sorted as the user chooses ([Artifacts page](./artifacts.md#artifacts-page)).

### Settings

Opened from **Settings** in the sidebar footer or with `Mod+,`. Settings takes the whole window: the app sidebar goes away, and the top bar holds a **Back** button after the window controls that returns to where you were. `Esc` does the same when no field has focus. While a session waits for your approval, the Back button carries the `--attention` count, so the signal the sidebar gave is not lost.

Each section is a page of its own, as in the reference, drawn in the [flat hairline direction](../milestones/m0-feedback.md#40-the-settings-pages-look-crude-and-their-colours-are-untuned): no cards and no shadows on the page, rows divided by hairlines under small group labels, and states as tinted pills. The hi-fi design is the [Settings canvas](https://claude.ai/artifact/4JfFPPaeUpjCpRBYdbyU16) of 2026-10-22.

- **The column** on the left, on surface 0 like the app sidebar it replaces, holds the title "Settings" in the heading role, a search field (`Mod+F`, with the hint at its end) and the sections in three clusters, 10 px apart: General, Appearance, Notifications and Keyboard shortcuts; Agents, Usage, Terminal and Git; Advanced and About. Each section row is 32 px high, taller than a sidebar row as in the reference, and leads with a 16 px Lucide icon in `--muted-foreground` that takes the label's color on hover and when selected: `Settings` for General, `SunMoon` for Appearance, `Bell` for Notifications, `Keyboard` for Keyboard shortcuts, `Bot` for Agents, `ChartNoAxesColumn` for Usage, `SquareTerminal` for Terminal, `GitBranch` for Git, `Wrench` for Advanced and `Info` for About. The selected section takes the row fill; choosing another replaces the page, which fades in over `--duration-fast` and starts at its top. A section with news for you ends in a 6 px `--checked` dot, named by its tooltip and accessible name: Agents while an agent update is available ("Update available: Codex").
- **The column's foot** is one 32 px row on the same grid: "OverBench" and the version in mono, then the updater's word at its end: "Up to date", "42% downloaded", or an `info` pill, "0.3.0 ready" or "0.3.0 is out", short enough to fit beside the version; anything longer truncates with an ellipsis. It opens About. It has no hairline above it and no dot.
- **The page** is a column centred in the area beside the list, at most 560 px wide, so a short page sits in balance on a wide window instead of in its top left corner ([problem 40](../milestones/m0-feedback.md#40-the-settings-pages-look-crude-and-their-colours-are-untuned)). It opens with the section's name in the title role and one line under it in the small role, `--muted-foreground`, saying what the page is for ("How OverBench looks: theme, size and motion."), 28 px above the first group.
- **Groups**: rows sit in groups 28 px apart, each under a 30 px label in 12 px, weight 500, `--muted-foreground` ("Input", "Sessions"). A label can carry a count and, at its end, the group's own quiet actions (**Check for updates**, **Hide accounts**, **Copy versions**, **Send a test notification**). Advanced's last group, **Danger zone**, has its label in `--destructive`.
- **Rows**: a `--border-soft` hairline above each row, the text in line with the title, the name (14 px, weight 500) and a one-line description (12 px, `--text-secondary`) on the left, the control on the right: `Switch`, a [segmented control](./design-system.md#patterns), or a quiet `Select` that has no border or shadow at rest and takes the `--bg-hover` fill on hover and while open, so a page of rows does not read as a form. A row that reveals more, such as Proxy's fields or an update's progress, keeps the same first line and puts what it reveals underneath. Changes apply at once, with no Save button.
- **Paths** (the data folder, an agent's configuration) are shown as places, not code: in the interface font, the folders in `--muted-foreground` and the last part at weight 500 in `--foreground`. A path too long for its row cuts the folders first, so the last part stays readable (a long name is cut at its end only once no folder is left), with the whole path in a tooltip. The separator before the last part goes with the folders, so a name whose folders are cut away does not read as a root path. **Copy path** (`Copy`, then `Check` for 1.5 s) and **Show in Finder** (`Folder`; Explorer, the file manager) are icon buttons with tooltips at the row's end.

**Search** filters rows in every section by name and description, and by the row's English name in any interface language, so a search for proxy finds 代理. While you search, the page gives way to the results: the title "Search results" with "3 results for "proxy"", then the matching rows grouped under their sections' names, each a link with its name and description and the matching text marked with `--mark`. The list shows the number of matching rows next to each section and dims the sections with none. Choosing a result opens its page (an agent's own page for an agent), scrolls the row to the middle and flashes it: a `--mark` fill held for 1.2 s, then faded out over `--duration-slower`. `Esc` in the field clears it, then leaves it; with no match, an `Empty` state says so.

### Settings › Agents

The page scales to many agents: a list first, and a page of its own for each agent.

- **The list** groups the agents under **Installed** and **Not installed**, each with its count, in catalog order. Installed means it can run now: an adapter agent whose adapter is not installed yet is listed under Not installed, since installing it is one click away, and moves to Installed when its install finishes. Each agent is one row of up to three lines, and the whole row opens its page through a button laid under its content, so the pill in it stays a button of its own.
  - The first line is the agent's tile (in grey when not installed) and name with its own version in mono (for Claude Code and Codex the CLI their adapter runs, never the adapter's version), then the row's one action as a pill next to the name, never as a button at the row's end ([rows](./visual-style.md#rows)); the state and a chevron sit on the right, the state only for an installed agent. The state is a dot with a word ("Sign in to start", "Starting…", "Failed"), except **Ready**, which asks nothing of the user and is the green dot alone, with "Ready" as its tooltip and accessible name.
  - The second is the account: the plan and the email, the email in `--foreground`; else what the agent needs (sign in, the error), what its install is doing (npm's latest line), "Reading the account…", or, for an agent that names no account, its config folder. One not installed says how it installs ("Not installed. Install sets it up through Homebrew.").
  - The third is the [plan limits](#usage-popover): up to two current windows, each with its percentage, the time left and a bar colored by [usage level](./design-system.md#usage-levels): neutral below 80%, `--warning` from 80%, `--danger` from 95% or once reached, the percentage in the matching text color. "Reading plan usage…" while they are read; "Plan usage shows once it runs" for an agent that reports them but cannot run yet; "No plan usage reported" for one that has none.
  - A row takes the `--bg-hover` fill on hover. Settings search finds an agent's row by name or account.
- **The pill** says what the row offers and keeps every state of it in place, so the row never changes its layout:

  | State            | Pill                                                                                                                                          |
  | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
  | Update available | `info`, `CircleArrowUp` "Update" and the new CLI version in mono; a click updates, the tooltip names the adapter's version                    |
  | Updating         | `info`, `Spinner` "Updating…" and an × that cancels                                                                                           |
  | Update failed    | `error`, `RotateCw` "Update failed, retry" with the reason as its tooltip, and an × that dismisses it                                         |
  | Updated          | `success`, `CircleCheck` "Updated", until the app restarts                                                                                    |
  | Installable      | `info`, `Download` "Install"; a click installs the way the agent's page has chosen, the tooltip names it                                      |
  | Installing       | `info`, `Spinner` "Installing…" and an × that cancels                                                                                         |
  | Install failed   | `error`, `RotateCw` "Install failed, retry", by the route the failed install took, with the reason as its tooltip, and an × that dismisses it |

  npm reports no percentage, so the pill never shows one; the latest line of its output stands on the row's second line instead.

  A failure whose retry no longer applies, because the agent was installed another way or the update is no longer offered, goes by itself. A request the host refuses outright, such as one while another task runs, shows as `error` "Install failed" or "Update failed" with its reason on the second line and an ×; nothing fails silently. An agent's page shows the same failures as notices, with **Retry**, **Copy log** and **Dismiss**.

- **The Installed label** ends with what applies to the whole list: when it last checked ("Checked 5 minutes ago", "Checked just now · 1 update", "Checked just now · all up to date", "Couldn't check for updates"), **Check for updates** (`RefreshCw`, a `Spinner` while it runs, the label kept), shown while any adapter agent is listed, and **Hide accounts** (`EyeOff`; **Show accounts** with `Eye` while hidden). Updates are also checked [by themselves](./agent-host.md#checking-for-updates), so the button is for when you want to know now.
- **Hide accounts** ([problem 26](../milestones/m0-feedback.md#26-account-details-cannot-be-hidden)) is a toggle button, `aria-pressed`, kept as `privacy.hideAccount` ([settings](./persistence.md#settings)) and off by default. While on, every email and account name in Settings, here and on Git's GitHub CLI row, is a run of dots behind a blur: illegible in a screenshot, withheld from copying, read out as "Hidden", and left out of search, so a match cannot reveal it. The rows keep their layout. Each mask is a button: hovering it takes the `accent` fill with the tooltip "Click to show", and a click shows that one value until it is clicked again ("Click to hide"), without opening the row under it or turning the setting off; hiding accounts again masks every value. One component (`Masked`) draws it, so a later screen that shows an account takes the same mask.
- **Fresh on every visit**: whenever the list or an agent's page shows, `agents.refreshAccount` starts each installed agent that reports an account or plan limits (Claude Code, Codex) and reads them; an agent that would need an install first is left alone, and a started one stops after the usual idle time. Meanwhile the account and windows the agent last reported, kept by the agent host across runs ([persistence](./persistence.md#what-is-stored-and-where)), stand in.
- **An agent's page** starts with **← Agents**, back to the list, which `Esc` also does before it leaves Settings. The title row is the agent's 40 px tile and its name as a button that opens a searchable list of the agents (Base UI's `Combobox`, as in the project menu), each with its mark and state, so moving between agents needs no trip back; the agent's actions sit at the row's end (**Retry**, the install link when OverBench cannot install it, **Sign out**). Under it, the state and how it connects ("Anthropic · through claude-agent-acp", "SST · runs in ACP mode itself"), then the sign-in methods or the error.
- **Notices** under the title, as `Alert`s, carry what is happening to the agent, one at a time:
  - **An update** (`info`, `CircleArrowUp`): "Codex 0.161.0 is available", the version you have and what updating does ("The new version installs next to it: running sessions keep going, and Codex uses it from its next start. If it cannot install, the current version stays."), and **Update**. While the user's own Claude Code or Codex runs and the update changes only the adapter, the notice names the adapter instead ("claude-agent-acp 0.95.0 is available", "You have claude-agent-acp 0.94.0, the adapter that runs your claude."), and says the agent keeps using that program.
  - **Updating** (`info`, `Spinner`): npm's latest line, its output so far in a scrolling log, and **Cancel update**. **Update failed** (`error`): the current version still works, the log, **Retry** and **Copy log**. **Updated** (`success`): "Codex is updated" and that it takes effect from the agent's next start.
  - **Install** for an agent that is not installed (`info`, `Download`): what installing does; for OpenCode, **Install with** as a quiet `Select` of Homebrew, the official script and npm, each one not found on this machine disabled with "not found", the command it runs in a mono box, **Install**, and **Installed somewhere else? Choose the program…**; for an adapter agent, that the adapter goes into OverBench's data folder and runs on your Node.js, and, when your own Claude Code or Codex was found, that it is used, with its version, if the adapter accepts that version, and that the agent is downloaded too otherwise. While it runs and when it fails, the notice turns into the same progress and failure notices as an update ([installing binary agents](./agent-host.md#installing-binary-agents)).
- The page then holds its groups, each a label over rows with hairlines between them:
  - **Version** (installed agents): the current version in mono, with the update state under it, a neutral dot and "0.161.0 is out" ("Adapter 0.95.0 is out" for an update of the adapter alone while the user's own CLI runs) or "Up to date" after the same dot, and when it was checked; adapter agents add **Check for updates**.
  - **Account** (installed agents): the plan for a subscription account ("Claude Max", "ChatGPT Free"), else the login method ("Anthropic API key", a cloud provider, a gateway); and the email, behind the mask while accounts are hidden. "Not reported" until the agent says.
  - **Plan usage** (installed agents): one row per window, its name and when it resets on the left, the bar colored by level and the percentage on the right; the label ends with when they were read and an icon button that reads them again. "Reading plan usage…" while they are read; **Check plan limits** for a stopped agent that can report them; otherwise a line saying the agent does not report plan usage.
  - **Configuration**: where the agent reads its own configuration ([agent configuration](./agent-host.md#agent-configuration)): the config folder, the settings file and the instructions file, each as a path with **Copy path** and **Show in Finder** when it exists, else "Not created yet", and the variable that moved it. OpenCode adds **Program**, the binary in use or "Found on PATH", with **Choose binary…**. Claude Code and Codex add **Program** too, the CLI their adapter runs ([using the installed CLI](./agent-host.md#using-the-installed-cli)): the installed program's path as a place, or "Bundled with the adapter", then the version in mono. When the bundled CLI is to run but the install was made without it, the row says "Bundled, not downloaded yet", with no version, and "Downloads with the next start, about 256 MB." under it. A line under it says why the bundled CLI runs: in `--attention-text` while the installed one was chosen and has a problem ("Your claude is 2.1.200; the adapter needs 2.1.303 or later.", "Your codex did not start, so the bundled one runs. Fix it, then retry.", with the reason on a line of its own, "Your claude cannot run without a shell."), in `--muted-foreground` when none was found ("No claude found on PATH."), since most people have none, and, when the bundled one was chosen, that the installed one is there too ("Your claude 2.1.304 is installed too."). Whenever the bundled CLI runs, the installed program's path follows as a place. A program that did not start gets a quiet **Retry**, which reloads the environment so the program is asked again. When a program was found, a segmented control chooses **Installed** or **Bundled**; choosing applies at once, and while the running agent still uses the other one, a line adds "Takes effect from the next start." (`AgentCli.active`). A program named by `CLAUDE_CODE_EXECUTABLE` or `CODEX_PATH` shows "Set by" the variable instead of the control, followed by its problem in `--attention-text` when it has one, since it runs anyway. This first version only shows these places; which settings each agent shows from them comes later.
  - **Advanced**, folded by default: the launch command with **Copy**, the adapter's package and version with **Reinstall**, and the Node.js version.

## Sidebar

- The top rows are the app's navigation: 32 px rows 2 px apart, each a 20 px icon in the text color and its name, as in the reference.
- A **New session** row (`Mod+N`) at the top opens [New session](#new-session), and stays highlighted while it is shown.
- An **Artifacts** row (`Shapes`) follows it. It opens the [Artifacts page](#artifacts) and stays highlighted while the page, or an artifact opened from it, is shown.
- A **Usage** row (`ChartNoAxesColumn`) comes next. It opens the [usage page](#usage) and stays highlighted while it is shown. Its end shows, in 12 px `tabular-nums` `--muted-foreground`, what Settings › Usage › **Show in the sidebar** chooses ([settings](./usage.md#settings)): today's tokens in the compact format ("1.4B", "13.7亿"), hidden while there are none; the tightest plan limit across the agents, as the agent's mark (12 px), the window and the used share ("5-hour 62% used"), colored by [usage level](./design-system.md#usage-levels); or nothing. The tightest limit is a reached window, else the fullest, as the agent menu picks it. Its accessible name says it in full ("Usage, Today: 1.4B tokens"; "Usage, Claude Code, 5-hour: 62% used"). Today's tokens are read again when the figures change and when the day turns. This row and the page's plan limits replace the plan usage chips the footer had ([problem 41](../milestones/m0-feedback.md#41-the-plan-usage-strip-is-unclear-and-needs-a-better-place)).
- The projects follow these rows with no header row above them. A project is added with `Mod+O`, File › Open Project…, or **Open project…** in New session's project menu.
- Projects are collapsible groups: folder name, with the full path in a tooltip. Clicking the name folds or unfolds the group; a project has no page of its own. The name is a group label, as the reference labels its groups: the small step at the medium weight in `--text-secondary`, with a 12 px fold chevron after it at all times, `ChevronDown` open and `ChevronRight` folded ([#127](https://github.com/overbench/overbench/issues/127)). Each project shows a **+** at the row's end at all times (shadcn's `SidebarMenuAction`), which opens New session in that project: the sidebar's one way to start a session there. A missing project has none.
- A project's row has a menu: hovering the row, or focusing it from the keyboard, shows a **More** button (`Ellipsis`) just before the **+** (at the row's end for a missing project), and it opens the same menu as a right-click, as does the context menu key (`Shift+F10`) on the focused row. The row keeps room for both buttons, so the name never runs under them. The menu holds **Import sessions…**, which opens a dialog of the sessions the agents already have for the folder (`agents.listSessions`), such as ones started in a terminal, grouped by agent, each with **Import**; an imported session joins the group and opens with its full history. This menu was decided while the maintainer was away (2026-10-22); to be reviewed.
- Sessions started with **No project** form a last group, **No project**, shown while it has any. It folds like a project's group and its **+**, shown on hover, opens New session with No project. It has no menu, since it has no folder to import sessions from. While one of its sessions is shown, `Mod+N` starts New session at No project.
- The sidebar's content is built from shadcn's `Sidebar` parts (`SidebarGroup`, `SidebarMenu`, `SidebarMenuButton` at `size="row"`, which is `--row-height`, 32 px, `SidebarMenuBadge`) with `collapsible="none"`, inside the `ResizablePanel` that owns its width. Rows have no border; hover and selection use the component's own fills, and a row keeps the hover fill while its context menu is open. The list scrolls behind [scroll-edge fades](./design-system.md#patterns), so rows fade out at the edges instead of being cut by the footer.
- Each row: the agent's [mark](./design-system.md#agent-marks) at 14 px, grey once the session's [prompt cache](#in-the-sidebar) is gone, title (truncated), and one status indicator in a 16 px slot at the row's end, kept when the row has none so a status appearing never moves the title. Rows show no time. The indicator, in this order of priority:
  1. **Waiting for you** (`attention: 'permission'`): an 8 px `--attention-dot` dot, named with the count ("Waiting for you, 2 requests"). This is the loudest signal in the app.
  2. **Error** (`attention: 'error'`): a destructive `CircleAlert` icon, until the session has been in front of you ([attention](./session-model.md#how-the-host-keeps-sessions)).
  3. **Running** (`status: 'running'`): the shared `Spinner` at 12 px in `--text-secondary` ([patterns](./design-system.md#patterns)).
  4. **Starting** (`status: 'starting'`): the same `Spinner` while the agent starts or the session loads, named "Starting". Running wins when both apply, so a row never shows two.
  5. **Prompt cache expiring**: an 8 px ring, a 1.5 px `--warning` border with no fill, in the cache's [last minutes](#prompt-cache), named with the time left ("Prompt cache expires in 4 minutes"). It goes once the cache has expired, and an unread session gets its dot back.
  6. **Unread** (`attention: 'unread'`): an 8 px `--text-tertiary` dot after a turn ended while the session was not in front, until you show it ([attention](./session-model.md#how-the-host-keeps-sessions)).
- Hovering a row, or focusing it from the keyboard, shows a **More** button (`Ellipsis`) over the indicator's slot, so the title keeps its width. It opens the same menu as a right-click, and so does the context menu key (`Shift+F10`) on a focused row.
- A session whose branch has a pull request shows its state icon after the title ([repository state](./design-system.md#repository-state)), as in the reference. Hovering the row shows the branch and the pull request in a tooltip.
- **Sub-sessions** ([session model](./session-model.md#sub-sessions)) sit under their parent, indented 16 px along a hairline `--border` guide line. A subagent shows the `Bot` icon with its title and, muted, its description ("Explore · Find where the tests read the clock"); a sub-session you started shows its agent's mark and title.

- A parent's indicator includes its sub-sessions: the waiting dot's count adds up their permission requests, and it shows Running while any of them runs, so a collapsed parent still says where to look.

The second is an agent mark greyed for a [prompt cache](#in-the-sidebar) that is gone, which the row's accessible name also says ("Prompt cache expired"); decided 2026-10-24 for [#189](https://github.com/overbench/overbench/issues/189). Error and running keep an icon and a spinner.
- The sidebar list has one Tab stop; the arrow keys move between rows.
- The footer holds **Settings**, with no shortcut hint (`Mod+,` stays in the app menu and Settings › Keyboard shortcuts), and, above it, a neutral `--bg-subtle` notice when an agent needs sign-in ("Codex needs you to sign in"); signing in is not an approval, so it takes no color. The notice opens Settings at Agents and is hidden while that section is open. The [update notice](#updates) sits between the two.
- Later, not in M0: pinned sessions with drag reordering, and grouping by status or date.

## Thread

The thread uses shadcn's `MessageScroller` with `autoScroll`: it follows new output, yields as soon as you scroll up, shows `MessageScrollerButton` to jump back, and fades both edges, so content slips under the top bar's `--border-subtle` hairline rather than being cut at it. The bottom is shadcn's own `scroll-fade-b` in `MessageScrollerViewport`; the top is `scroll-fade-top-overlay`, a `--background` gradient drawn over the scroller whose opacity follows the scroll position, because a mask that fades the top made Chromium repaint the thread on every streamed chunk ([results](../perf/m0.md)). Focused from the keyboard, the thread shows an inset `--ring` ring drawn over the scroller, since the bottom fade would mask one on the viewport and an outer one would be clipped at the window's edge. No message is a `scrollAnchor`: to let an anchor reach the top, `MessageScroller` pads the thread's end with a spacer, and after a short reply that padding stayed as empty room to scroll into. A thread shorter than the view does not scroll at all. Sending a message, steered or not, scrolls to the end even while you read further up, and the thread then follows the reply as it streams. Opening a session lands at the bottom.

M0.3 compares its behavior with the reference's measurements: following within 40 px of the bottom, your own scroll winning over following for 150 ms, jump-to-latest beyond 120 px, and instant rather than smooth following. Where `MessageScroller` differs and offers no option, OverBench keeps its behavior and records the difference here; it never adds a second scroll hook.

Against `@shadcn/react` 0.3.1:

| Scroll behavior | Instant following              | Instant following; the jump button scrolls smoothly                                                             |

### Turn status

While a turn runs, a status line stays at the thread's end, from the prompt to the turn's end: `role="status"`, the small step in `--muted-foreground`, with a small `Spinner`, the time since the turn began, the tokens the turn has added and what the agent is doing now, as "49 m 8 s · 36.6K tokens · Thinking". A subagent's thread shows it without the time, since only the turns you send set `turnStartedAt`. The clock ticks once a second in a component of its own, so the thread never re-renders for it, and only the phase is announced. The tokens are how far the context the agent reports has grown since the turn began (`usage.used` against `turnStartUsed`), shown only while that is positive: Claude Code reports the context after each response (claude-agent-acp 0.94, read in its source on 2026-10-23), other agents may report it only when the turn ends, a session's first turn has no context to start from, and a compaction leaves less than there was. The phase comes from the turn's latest entries, looking past plans, notices, git events and subagent cards:

- "Thinking" while a thought streams, and "Writing" while a message is the latest output.
- The latest tool call at the end that still runs, with how many of its kind run at once: "Running a command", "Reading 2 files", "Searching", "Fetching a page", "Editing a file" (edits, moves and deletions).
- "Compacting context" while a compaction runs, and "Waiting for your approval" while a permission request is pending.
- "Working" otherwise: before the first output, between steps, and for tool calls without words of their own.

A turn the agent's exit cut short ends in a line of its own, in place of a turn-end marker: the host's notice, marked `cause: 'agent_stopped'`, shown as an `Alert` in the `error` variant, the destructive soft tint, with `CircleAlert` and "Claude Code exited before finishing this turn". While it ends the thread's latest turn and the session is `ready` or `closed`, it offers **Resume**, which sends "Continue" in the app's language through the queue, as the composer does, and so attaches the session again; a failure shows under the line. Older ones show the line without the button.

### Message actions

Every turn with a reply ends in one row, after its last entry, in place of its turn-end marker: **Copy** (every message of the turn's reply, as markdown) and **Fork into a new session**; then the turn-end text and when the reply began ("Worked for 1 m 9 s · just now"). The buttons are quiet `icon-xs` buttons with tooltips. The row is hidden under every reply, the latest one too, and shows while the pointer is over the reply, from the first entry after the user message to the row itself, or while it holds keyboard focus; it holds its place, so the text does not move. A turn from a replay has no end marker and no times, so its row holds the buttons only. The turn still running gets its row when it ends.

Fork starts a new session with the conversation up to the end of that reply's turn, and shows it. It shows when the agent supports `session/fork`: under every reply for an agent that forks at a message (Claude Code and Codex), else under the latest reply only, which forks the whole session ([fork from a reply](./session-model.md#how-the-host-keeps-sessions)). It works in a `ready` or `closed` session and is disabled in any other, such as while a turn runs. Rewinding to a message and pinning are left for later.

### Markdown

- Streamdown in `streaming` mode, which splits the text into memoized blocks, with `parseIncompleteMarkdown` and the caret while the message streams. The mode never changes: `static` mode renders one tree, so switching to it when a message finishes would rebuild the whole message.
- Plugins: `@streamdown/code` for Shiki highlighting, with a light and a dark theme matched to the app's tokens, and `@streamdown/cjk` so emphasis and line breaking work around Chinese, Japanese and Korean text.
- **Line breaks**: a single line break is a line break (`remark-breaks`), not the space CommonMark makes of it. Agents write for their own terminals, which keep every line, and a command's plain output depends on it: Claude Code's own `/usage` text, which the adapter forwards when its report times out, is one line per limit and per measure.
- `skipHtml` is on: agent output never renders raw HTML. Links pass through Streamdown's link safety and open in the system browser. A GitHub pull request URL renders as a [pull request chip](#pull-requests) instead of a plain link.
- **File references**: inline code or a link that names a file of the session's project is a chip that opens that file in the [Files](#files) pane, at the line when it gives one. Recognised forms: a relative path (`src/x.ts`, `./src/x.ts`), a path with a line (`src/x.ts:12`, `src/x.ts:12:5`, `src/x.ts#L12`), and an absolute path inside the project. Only paths in the project's file list count, so an identifier in backticks stays plain code; a media file is the exception, checked on disk instead, since agents write their renders into git-ignored folders ([media](./media.md#files-on-disk-the-conversation-names)). The chip shows the file's [type icon](./design-system.md#file-icons) at 12 px and its name, with `:12` after it for a line and the full path as its tooltip, so a file and a web link are told apart at a glance. A link to a local path that is not a project file shows its text alone. Link hardening blocks relative links, so a remark plugin (`local-links.ts`) carries a local link's target in a `#local:` fragment past it.
- **Typography**: [Design system: prose](./design-system.md#prose) has the measurements, the typography spec of [problem 43](../milestones/m0-feedback.md#43-the-message-body-needs-a-typography-pass-to-a-given-spec). Emphasis in Chinese text is a step of weight instead of italics.
- Code blocks are Streamdown's, with its copy button in a 32 px header beside the language.
- **SVG**: a complete `svg` code block shows its picture, with **Show source** (`Code`) beside the copy button and **Show preview** (`BookOpen`) back, as the Files pane does for Markdown; the choice is the block's own. The picture is an `<img>` from a `data:` URL, so none of its scripts run and nothing it references loads. The text goes through the HTML parser first, as SVG written into a web page does, so a missing `xmlns` or an `&nbsp;` still draws. It shows at its own size, never wider than the block, on a white page ([measurements](./design-system.md#prose)), and its `<title>` is its alt text. While the block streams, and when it holds no `<svg>` or does not decode, it is an ordinary code block.
- **Images**: a Markdown image that names a local file shows where it is written, from the [media scheme](./media.md#the-media-scheme); one with an `http(s)` source is never loaded, since the CSP blocks remote images, and shows as a link chip with its host. Raw HTML stays off, so no `<img>`, `<video>` or `<audio>` tag from a reply ever renders.

### Tool calls

```text
 ✎  Edit  src/auth/login.test.ts                           +12 −3   ✓
    ┌──────────────────────────────────────────────────────────────┐
    │  (the diff, when the row is opened)                          │
    └──────────────────────────────────────────────────────────────┘
```

- **Row**: tool calls are records, never bordered cards, so they weigh clearly less than the answer. A tool call is a 24 px row at 13 px in `--muted-foreground`, reaching 6 px past the column on each side so its icon lines up with the prose; when it has details, the row is the toggle of a `Collapsible` and takes the `--accent` fill on hover. The details open under it, indented to the text: the command, the output and the diff, which is framed like a code block. Only a request for permission keeps a card ([below](#permission-requests)).
- **Row content**: the kind icon (14 px, swapped for the chevron under the pointer), the verb, the path or command, a summary on the right (diff stats in `tabular-nums`, the permission answer) and the status:
  - `pending`: a hollow circle.
  - `in_progress`: a spinner.
  - `completed`: a check in `--icon-default` that fades in; success takes no color.
  - `failed`: a destructive cross, and the row opens to show why.
- **Kind icons** (Lucide): `read` FileText, `edit` FilePen, `delete` Trash2, `move` ArrowRightLeft, `search` Search, `execute` SquareTerminal, `think` Brain, `fetch` Globe, `switch_mode` Repeat, `other` Wrench.
- **Paths and commands** are monospace, middle-truncated so the file name stays visible, with the full value in a tooltip.
- **Content**: markdown through Streamdown, finished from the start; diffs through `@pierre/diffs` `MultiFileDiff` in `unified` style with wrapping, at most 480 px high with **Show full diff**; images, video and audio in the content, or named by the call's locations, as in a reply ([media](#media)), images at most 160 px high.
- **Folding a run**: the agent's work between messages (thoughts, tool calls, plan updates and compactions) folds into one `text-ui` `--text-tertiary` line, its file names in `--text-primary` and its diff stats `+N` in `--success` and `−N` in `--danger`, that says what it did, one part per kind in the order it first appears, joined by " · ": "Read README.md, plan.md and 6 more · Created offload.py +122 −0 · Ran 5 commands ›". The text starts on the prose's left edge and a 14 px chevron follows it, so every line of the reply starts at the same place; the line takes the `--bg-hover` fill and a 6 px radius on hover. Two or more steps fold, and so does a lone tool call, which then reads as any other work ("Push the branch and open a draft PR ›") instead of a row with its icon, command and check.
  - **Files**: a part names up to two files by their names, in the order they were first touched, and counts the rest, "and 6 more"; a file read twice counts once, and two shown files that share a name add the fewest folders that tell them apart ("src/index.ts, test/index.ts"). Calls that give no path are only counted ("Read 3 files"). An edit's files are the paths of its diffs, else its locations, since Codex sends a patch's files only in its diffs (codex-acp 2.2.2, checked on 2026-10-23), so a patch adds each of its files to its part. A file whose diff has no old text was created: it is in a Created part, with the edits that follow it in the run. Each file's diff stats follow its own part.
  - **Commands**: one command is named by its description, "Reran CPU content diff with full key map". Several are counted, "Ran 6 commands", followed by the latest command's description when it has one. Claude Code's `Bash` calls carry one in their input, as `description` or `command_description`, which its CLI also accepts; Codex and OpenCode send the command alone, so their commands are counted (checked on 2026-10-23 with claude-agent-acp 0.94.0, codex-acp 2.2.2 and OpenCode 1.19.4). Without a description, one command is "Ran a command". The host keeps a description to one line of at most 200 characters.
  - Failures add "1 failed" in `--danger`, and a step still running adds a spinner. A line too long for the column is cut with an ellipsis and shows in full in a tooltip, which only a cut line has. The line expands, as a disclosure, to the steps beside a 1 px `--border-subtle` rule, 6 px in and 14 px from the steps. Messages never fold: what the agent says to you stays in view, as in the reference, and only the work between two messages folds. A subagent, a notice or a git event ends a run, since each is something to see or act on. A lone thought, plan or compaction stays as it is, and so does a lone tool call waiting for permission, which keeps its card. The run a turn is still adding to shows step by step and folds once a message or the turn's end follows it, so the current work stays in view. A step waiting for permission holds its run open.
- **Progress notes**: Codex writes short notes before its tool calls ("Checking the build scripts next") and marks them `commentary`, apart from its `final_answer`, but codex-acp passes the mark to JetBrains AIR clients only. So for an agent the catalog marks with `progressNotes`, today Codex, a message that more work in its turn follows counts as a note, since Codex ends a turn with its answer: it folds with the work around it, in the run, as a 13 px `--muted-foreground` paragraph, and the turn reads as one run above its answer. The answer is the turn's last messages, and Copy takes only those. While the turn runs, its notes show as they stream and its work does not fold, since a message still streaming may be a note; when it ends, everything before the answer folds.
- **Grouping**: inside a run, consecutive completed `read`, `search` and `fetch` calls collapse into one row, worded like a run's line ("Read a.ts, b.ts and 2 more · Searched 3 times") and cut the same way, which expands to the individual calls.
- **Defaults**: running rows and requests waiting for permission are open; completed rows are collapsed.

### Permission requests

```text
┌──────────────────────────────────────────────────────────────┐
│ ▶  Run  pnpm test --filter auth                    Waiting  │
├──────────────────────────────────────────────────────────────┤
│  Claude Code wants to run this command.                      │
│                                                              │
│  [1 Allow once]  [2 Always allow]  [3 Reject]                │
└──────────────────────────────────────────────────────────────┘
```

- The request lives in the tool card it belongs to. The card takes the [attention ring](./design-system.md#elevation), pulses once, and scrolls into view; its header shows "Needs approval" with an `--attention` dot in place of the status icon.
- The diff or command being approved is visible inside the card, so you judge it before you answer.
- Options appear in the agent's order. `allow_once` is the primary button and the others are `outline`: rejecting is neither a failure nor a deletion, and the card's attention ring is already its one color.
- Number keys `1` to `4` pick an option when the composer is empty and not focused; within the options, the arrow keys move focus.
- While a request is pending, the composer shows "Waiting for your approval" and the session's sidebar row shows the attention dot.
- After an answer the buttons give way to the choice made ("Allowed once"), shown in the card's header so the history reads clearly even with the card closed.

### Media

> Option A of the [media design](./media.md#options), chosen 2026-10-24 and built in steps from its [first version](./media.md#first-version). What counts as media, where it comes from and how files reach the renderer are in [media](./media.md).

- **Where**: a Markdown image shows where it is written; a media file that a [file reference](#markdown) names shows under the block that names it (a paragraph, a list item, a table), in the order named and once per message; images and sounds the agent sent as content follow the text with the other attachments; media in a [tool call](#tool-calls) shows in its details. The file chip stays in the sentence and still opens the file in the [Files](#files) pane.
- **Images**: at their own size, up to the column's width and 288 px high. A `rounded-xl` frame with a hairline `--border` ring drawn over the picture, `--border-strong` under the pointer; a transparent picture over `--checker` on `--card`. Images next to each other flow in a row, 6 px apart. Each is a button named "Open image" and its alt text, and a click or `Enter` opens the [viewer](#viewer).
- **Video**: the column's width at its own aspect ratio, at most 480 px high (a portrait clip is narrower, aligned to the start), in the same frame, with Chromium's controls: `preload="metadata"`, no autoplay and no loop, and `controlslist="nodownload"`, since saving is the viewer's **Save as…**. Under it a caption row: the file's [type icon](./design-system.md#file-icons) at 12 px, its name, and its length and size in the meta role; then, on hover or focus, **Open larger** (`Maximize2`), which opens the viewer at the same moment, and **Show in Files** (`Folder`), or **Show in Finder** for a file outside the project.
- **Audio**: Chromium's audio controls, as wide as the column up to 420 px, with the same caption row but no **Open larger**.
- **Spacing**: a media block takes a paragraph's spacing, `0.75em` below it.
- **One at a time**: starting a clip or a sound pauses any other in the window. One scrolled out of view goes on playing.

#### Viewer

- **What**: a layer over the whole window, Base UI's `Dialog` in a `viewer` variant, on a `--viewer-scrim` that is dark in both themes, since pictures and video read best on dark. It holds the session's images and videos in thread order as far as the loaded pages reach, the user's attached images and folded runs included, so a screenshot inside a folded run is an arrow away.
- **Bar**: 40 px, laid out as the top bar, clear of the traffic lights and the window controls: the name (interface role, 500), its pixel size and file size (meta), the position ("3 / 7", meta), then **Zoom out** (`Minus`), the zoom level as a button that toggles fit and 100% (meta), **Zoom in** (`Plus`), **Copy image** (`Copy`, then `Check`), **Save as…** (`FileDown`), **Show in Files** (`Folder`) and **Close** (`X`). A video has no zoom and no copy.
- **Stage**: the item fitted inside the stage less 48 px on each side, never enlarged past its own pixels; a transparent picture over `--checker` on `--card`. **Previous** and **Next** (`ChevronLeft`, `ChevronRight`), 32 px round buttons on `--popover` with the `md` shadow, sit at the stage's edges, show on hover and on focus, and go at the ends.
- **Zoom**: from the fitted size up to 800% of the image's own pixels. A pinch, or `Mod` with the wheel, zooms around the pointer; the buttons and keys zoom by steps of 1.25 around the centre; a zoom that ends within 5% of the fit snaps back to it. From 300% of its pixels an image renders pixelated, so its pixels stay crisp.
- **Pan**: once zoomed, the wheel and a drag pan, the drag only after 4 px so a click stays a click; the image stops 24 px past its edges. A double-click toggles fit and 100% at the pointer. A click on the scrim, not on the item, closes.
- **Keys**: `Esc` closes; `←` and `→` step, `Home` and `End` go to the ends; `+` and `-` zoom; `Shift+1` fits and `Shift+0` shows 100%; `Mod+C` copies the image. While a video's controls have focus they keep their own keys. Focus moves into the viewer and returns, on close, to the item that opened it.
- **Video**: the viewer takes over the inline player's moment and state, playing on if it was playing, and hands them back on close.
- **Motion**: the item grows from its place in the thread to its fitted place while the scrim and the bar fade in, the [viewer pattern](./design-system.md#patterns); closing returns it to its place when that is in view, and fades otherwise. Stepping crossfades with a 24 px slide. Zoom from the buttons and keys eases over `--duration-fast`; a pinch, the wheel and a drag follow at once. With reduce motion, opening, closing and stepping fade, and zoom changes at once.

#### Media states

Each state takes the item's reserved box ([media: states](./media.md#states)):

- **Loading**: a `Skeleton` at the reserved size, after 200 ms.
- **Missing, a format that cannot play, a read error**: a placeholder frame at least 96 px high on `--card`, `rounded-xl` with the `--border` ring, holding the file's type icon and name (interface role, 500), one line saying why (caption role; a read error's title in `--destructive` with `CircleAlert`, and the system's error under it in mono), and its `xs` outline buttons: **Retry** (`RotateCw`) when the file is missing or unreadable; **Open with default app** (`ExternalLink`) and **Show in Finder** (`Folder`) for a format Chromium cannot play.
- **Remote**: a link chip with `ExternalLink` and the source's host, which opens in the system browser.

## Composer

The layout follows the reference: the box holds the message, its text, its [attachments](#attachments), **+** and the send button, and the session controls sit in a row under it. The box stays quiet, and the controls read as settings rather than as part of the message.

```text
┌──────────────────────────────────────────────────────────┐
│ ┌──────┐ ┌──────┐                                        │  attachments, while there are any
│ │ ▤    │ │░░░░░░│                                        │
│ │ui.md │ │░░░░░░│                                        │
│ └──────┘ └──────┘                                        │
│ +  Ask Claude Code to…                                 ↑ │  composer, 52 px for one line
└──────────────────────────────────────────────────────────┘
  Default ⌄                              Opus 5.5 High ⌄  ◔    control row, 28 px
```

- **Surface**: shadcn's `InputGroup` with an added `composer` variant: raised (surface 3), `rounded-2xl`, and the composer's ring and shadow states from the [design system](./design-system.md#elevation).
- **Text**: `InputGroupTextarea`, which grows with `field-sizing: content`, from `--composer-min` up to `min(40svh, 24rem)`, then scrolls. Typing at the end of a long draft keeps it scrolled to the bottom, padding included, because a textarea scrolls only the caret into view and would leave the last line on the edge. The placeholder is "Ask <agent> to…".
- **Send button**: a 28 px round `InputGroupButton` at the end of the last line; `--primary` when there is text or an attachment, `--muted` and disabled when empty.
- **Add**: a 32 px round `quiet` `InputGroupButton` (`Plus`) at the start of the last line, mirroring Send, which opens the [attachments](#attachments) menu; the text starts after it.
- **Control row**: a `--row-height` row under the box, outside it, built from `config`. On the left, the mode selector. On the right, one model button that shows the model and, when the agent offers `thought_level`, the reasoning level after it ("Opus 5.5 High"), in `--text-secondary` whatever its tier; then the usage ring. The controls are ghost buttons at `--control-height` in `--text-tertiary`; the model name and the level are `--text-secondary`. For a `provider/model` name, such as OpenCode's `opencode-go/GLM-5.3`, the button shows only the model part, with the full name in its tooltip. Any other `select` option gets its own button in the row, placed by `category`; its menu closes once a choice is made.
- **Model menu**: one 320 px menu (`w-80`) for the model, the reasoning level and the boolean options, so a model and its level are set together. Choosing a model closes it, whether by a click, `Enter` or `1` to `4` for the first four models. The reasoning level, which `←` and `→` step, and the switches keep it open, so a level and options can be set in one visit; `Esc` or a click outside closes it. The model list comes first under its option's name, the current model checked; each row shows the model's name and, when the agent gives one, its description in muted text, and a `provider/` prefix in `--muted-foreground`. A long list, such as OpenCode's dozens of models, scrolls by itself within 288 px (`max-h-72`) with [scroll-edge fades](./design-system.md#patterns), and opens scrolled to the current model, so the reasoning level below it stays in view. The boolean options follow as switches, after a separator.
- **Reasoning level**: the levels are ordered and one is always chosen, so up to six of them show as a [segmented control](./design-system.md#segmented-controls) under a row with the option's name. The control spans the menu's full content width, like the rows above it, with 6 px of padding inside each segment; more than six levels fall back to a list like the models'. A choice named Default leaves the level to the agent, so it is one of the levels in effect and gets no segment: while it stands, the thumb rests on the level its name or description names ("Default (High)"), or on none when the agent does not say, and the row shows "Default" on the right; once a level is set by hand, a reset button (`RotateCcw`, "Use the agent's default") takes its place. The model button leaves a Default level out. A click on a level chooses it. Pressing captures the pointer: while pressed, the thumb snaps segment by segment under the pointer and shrinks to 97%, and the label follows it; the segment under the pointer is chosen on release, so the agent gets one request. The thumb slides with `translate` over `--duration-base` and `--ease-out-quart`, and moves at once with reduce motion. The top levels are recognised by name, compared without case or dashes: **Xhigh**, Extra high and Very high are the high tier, **Max**, Maximum, Ultra, Ultrathink and Ultracode the max tier. A level's name takes no color of its own, whatever its tier: the gradients and the tinted thumb ring the tiers had are gone with the palette's rule ([model names](./design-system.md#model-names-and-reasoning-levels)); the max tier keeps one neutral sheen that sweeps across the thumb when it lands there.
- **Ultracode**: a switch after Fast mode in the model menu, for Claude Code sessions whose reasoning level offers the high tier (`xhigh`), since ultracode needs it; it also shows while on. It turns on, for the session, a dynamic workflow on every substantial task, and restarts Claude Code to do it, so it changes only between turns: during a turn it is disabled and says "Changes between turns". While it is on, the control row shows **Ultracode** in the max tier's gradient before the model button ("Ultracode is on for this session"). A message that says `ultracode` still turns it on for that message alone, and the same label shows while such a draft is written ([session model](./session-model.md#config-options)).
- **Picks show at once**: a chosen model or level shows immediately. The agent's own value arrives with the session's next patch, after the request has settled, so the pick stands until that value lands, the request fails (the error shows in the control row and the old value returns), or 1.5 s pass.
- **Sending**: **Enter** sends and **Shift+Enter** inserts a newline.
- **IME**: Enter never sends while an IME composition is in progress (`isComposing`, or `keyCode` 229), so Chinese, Japanese and Korean input works. The reference also drops an Enter that arrives within 500 ms after `compositionend`, a guard for WebKit. M0.3 tests Pinyin and Japanese input on all three platforms (the macOS input sources, Microsoft Pinyin and IME, fcitx5) and adds such a guard only where a test shows it is needed, with the shortest window that passes.
- **Drafts**: unsent text and its attachments are kept per session and restored when you come back, also after a restart; sending clears them ([persistence](./persistence.md#composer-drafts)).
- **Slash commands**: `/` at the start opens a `Command` popover with the agent's `available_commands_update` list, filtered as you type; choosing one inserts `/name ` and shows its input hint.
- While a turn runs, the send button becomes a round **Stop** and `Esc` cancels the turn. A message written meanwhile is either queued or steered:
  - **Queue** (the send key, or the `ListPlus` button that appears beside **Stop** while there is text): the message waits in the queue and is sent when the turn ends.
  - **Steer** (`Mod+Enter`, or `Mod+Shift+Enter` when `Mod+Enter` sends): the message goes into the running turn, for an agent that supports it, and shows in the thread with a muted `CornerDownRight` "Steered" label under the bubble. Claude Code supports it; Codex and OpenCode only queue ([session model](./session-model.md#queue-and-steering)).
  - The placeholder names the keys after the usual prompt: "Ask Claude Code to… ↩ to queue, ⌘↩ to steer", or "Ask Codex to… ↩ to queue" for an agent that only queues.
- **Plan row**: the latest plan, while it has steps left or a turn runs, sits in one `--row-height` row above the composer, its text in line with the composer's: `ChevronRight`, "Plan" in `--text-tertiary`, a 14 × 4 px segment per step (done in `--text-secondary`, the current step in `--text-tertiary`, the rest `--border-default`; past eight steps the segments share 112 px), the count ("4/6") and the current step at the medium weight in `--text-primary`, truncated. A click opens the whole list under the row, which pushes the row up, as a disclosure; past 168 px the list scrolls inside, behind scroll-edge fades. The list's steps are `--text-tertiary` and the current one `--text-primary`. The row takes the `--bg-hover` fill on hover.
- **Queue stack**: while anything waits, the queued messages are a stack of cards tucked behind the composer's top edge, which covers each card's last 8 px. Folded, the next message shows ("Next", its text and "5 queued", or "Paused · 5 queued"); a message that carries attachments adds "· 2 attachments" after its text in `--text-tertiary`, or shows that alone when it has no text with up to two edges 6 px above it, each narrower; the stack keeps that room above the composer, and an empty queue takes none. Resting the pointer on it for 150 ms, or focusing it, fans out three cards 36 px apart, each on `--bg-surface` with a `--border-default` hairline and the queue shadow, each further one 3% narrower and its fill nearer `--queue-back`, with a 6 px edge above them while more wait; the front card's count turns into its place ("1 / 5"). The wheel and `↑` `↓` move through the queue: the front card slides down behind the composer and the next comes forward, the cards follow the wheel at `--duration-fast` and settle on a whole card 120 ms after it stops; a notch moves one card. Only the card under the pointer, or the front one from the keyboard, shows its actions at its end over a fade: **Resume** on a paused queue's next message, **Send now** (`CornerDownRight`, the tooltip "Steer now: send into the running turn") where the agent steers and a turn runs, **Edit in the composer** (`Pencil`), which moves the text and its [attachments](#attachments) back into the draft, and **Remove** (`X`). Other cards' actions are inert. The stack folds 180 ms after the pointer leaves, when focus leaves it, or on `Esc` wherever focus is, even in the composer, so that Esc folds it before a second one cancels the turn. Focus never drops to the page: an action whose card goes or folds hands it to the stack, and the last message going hands it to the composer. A failed action shows its error above the composer until the next action or until the queue empties. While it is fanned out the plan row fades out and up 4 px over `--duration-fast`, and comes back as it folds, so the two never overlap. The cards move with Motion's `card` spring, a sent or removed message slides down behind the composer as it goes, and a new one fades in at its place; with reduce motion only opacity changes. After **Stop**, a failed turn or a restart the queue is paused until **Resume**. Sending while the session is idle goes at once, beside a paused queue. Built from the [thread view canvas](https://claude.ai/artifact/WcTFKxRQFdmoghoE8vCDkT) ([#96](https://github.com/overbench/overbench/issues/96)), which shows a menu of further actions in place of **Edit**; with one action behind it, the menu would cost a click for nothing.
- While a permission request is pending, the placeholder reads "Waiting for your approval" and the send button is disabled.
- While the agent is starting, the text area is disabled and the control row is hidden, because the config options are not known yet.
- **Usage**: a 16 px pie inside a thin ring showing `used / size` of the context, alone at first; a filling wedge, unlike a short arc, never reads as a spinner. From 80% it turns `--warning`, from 95% `--danger`, and shows the percentage next to it. When a plan limit of the agent's account reaches its warning state, its window and percentage appear in front of the ring in its [usage level](./design-system.md#usage-levels) ("5h 92%"); once a limit is reached, the composer's placeholder says when it resets. A click opens the [usage popover](#usage-popover).
- **Prompt cache on the ring**: the ring stays as it is while the [prompt cache](./session-model.md#prompt-cache) is warm, and shows two quiet states between turns, in shape and not in color: in the cache's [last minutes](#prompt-cache) its track turns dashed (twelve dashes), and once it has expired the wedge also fades to 35%, the dimming the data graphics use for what lies outside. In both, the time shows before the ring, as [in the control row](#in-the-control-row) says. The button's accessible name says which ("Context 5% used. The prompt cache has expired."), "probably" for an estimate. The states change on a timer set for the moment each one starts, and are checked again on each tick of the shared 30 s clock, since timers stand still while the computer sleeps and do not follow a change of its clock; a check that finds the state unchanged renders nothing, so the ring re-renders twice per request. During a turn the requests keep the cache in use, and the ring shows neither. Reviewed 2026-10-24 for [#189](https://github.com/overbench/overbench/issues/189).

### Attachments

> Decided 2026-10-23 for #40: of three options tried on the [comparison page](https://claude.ai/artifact/MDCp3YWNX49NKR4wUqTvvu), the maintainer chose A, tiles in the box, over chips under the box and references inside the text. Pasting images is built ([#134](https://github.com/overbench/overbench/issues/134)), and so are **+** and dropping files and folders ([#135](https://github.com/overbench/overbench/issues/135)) and `@` mentions in a session ([#137](https://github.com/overbench/overbench/issues/137)); the other ways in are to be built.

Files, photos and folders a message carries besides its text. The host sends each one as the agent's prompt capabilities allow ([session model: attachments](./session-model.md#attachments)); this section is what the user sees. The looks are in the [design system](./design-system.md#attachments).

**Ways in.** Four, all adding to one list per message, at most 20:

- **+**: its menu holds **Add files or photos…** (`Mod+U`), **Add folder…**, a separator, then **Mention a file** with `@` and **Slash commands** with `/` as their hints; the last shows only when the agent lists commands. The first two open the system's file dialog, starting in the session's folder. The last two put `@` or `/` at the caret and open their popover, so the typed ways in can be found from the menu; **Mention a file** puts a space before the `@` when the caret follows a word, so the `@` starts one. A command starts a message, so **Slash commands** puts `/` in an empty box, and with text in the box is disabled, saying "In an empty message" where its hint was. The menu opens above **+** and gives focus back to the text when it closes. The tooltip says "Add files, photos or a folder" with `Mod+U`, which works anywhere in the session and joins the [keyboard](#keyboard) table with the build.
- **Paste**: an image on the clipboard, such as a screenshot, becomes "Image 1", "Image 2" in the order pasted; files copied in the file manager are added as files. Text stays text, except a paste longer than 10,000 characters, which becomes a **Pasted text** attachment so the box stays light; its preview offers **Paste as text** to put it back in the box.
- **Drop**: dragging files or folders over the session fades in the [drop overlay](./design-system.md#attachments) on the thread column, the session's header, thread and composer, over `--duration-fast`, saying "Drop to attach" over "Files, photos or folders · up to 20". A drop anywhere on the column adds them. Only a drag that carries files shows it, so dragging text into the box works as before; the sidebar and the side panel are not targets. An image dragged out of a page, with no file on disk behind it, is added as a pasted one is; anything else without a file fails with "It isn't a file on disk, so it can't be attached."
- **`@` mentions**: `@` at the start of a word opens a popover of the session folder's files and folders where the [slash popover](#composer) opens, filtered as you type with the Files pane's matcher, best first, at most 50 rows. A row is the [file type icon](./design-system.md#file-icons) at 16 px, the name with its matched characters marked in `--mark`, and the folder in `--text-tertiary`; a folder's name ends in `/`. With nothing typed it lists the files this session's tool calls read or edited, most recent first, under "Used in this session", then a line with how many there are to search ("Type to search 2,481 files and their folders"). `↑` and `↓` move, `Enter` or `Tab` chooses, `Esc` closes and keeps the text; with no match, `Enter` sends as usual. Choosing replaces `@query` with `@name ` in the text, so the sentence still says which file it means, and adds the file; the two are independent from then on. Without a project chosen in [New session](#new-session) the popover says "Choose a project to mention its files".
  - **Built for [#137](https://github.com/overbench/overbench/issues/137)**, accepted by the maintainer on 2026-10-24: the name written is the file's, or the folder's with `/` after it, in place of what was typed up to the caret, so text after the caret stays. The folders are those that hold a listed file, since the [Files](#files) list holds files only. The full-width `＠` some input methods type opens it too. The project's files are listed again as each `@` starts, so files made since show up, and "Used in this session" covers the loaded part of the thread. Before the list has arrived, the line under the rows says "Listing the project's files…" after a `Spinner`; a list that failed shows its error there in `--danger`. With nothing typed and no file used yet, the popover is that line alone and `Enter` sends. `Esc` or a click elsewhere closes it for that `@`, which stays closed while it is typed on, as the slash popover does. **Mention a file** stays enabled with 20 attachments: choosing then writes the name, adds nothing, and the line under the box says "Only 20 attachments fit in one message". The matcher ranks the best 50 without sorting every match, about 4 to 11 ms a keystroke over 50,000 paths and their folders, and the typing never waits for it. New session's `@` comes with its attachments ([#139](https://github.com/overbench/overbench/issues/139)).

**Tiles.** The attachments sit in one row inside the box, above the text, in the order added, as 112 px tiles. The row scrolls sideways once it is full, behind scroll-edge fades; a vertical wheel scrolls it too.

- An image is its thumbnail. A file or folder shows its type icon, then its name, cut in the middle so the extension stays (`ci-failure-…-1042.log`), and its size or "Folder". A pasted text shows its first three lines and its line count.
- Hover or focus shows **Remove** (`X`) at the tile's top right; it holds its place. The tooltip gives the name, the size, an image's pixel size and how the agent gets it: "Sent with its contents", "Sent as a link. Codex reads it with its own tools.", "Sent as an image, scaled to 2000 × 1250".
- A click, `Enter` or `Space` opens it: an image in its [dialog](./design-system.md#attachments), and in the [viewer](#viewer) once that is built, with the thread's other pictures an arrow away (proposed with the [media design](./media.md); to be agreed); a pasted text in the same dialog as code; a project file in the [Files](#files) pane; any other file or folder in the file manager.

**States.**

- **Adding**: a tile appears in the next frame with its name. Only after 200 ms does an image show a `Skeleton` square, or a file a `Spinner` before "Reading…", until its read ends.
- **Sent another way**: an image for an agent without image input gets a `TriangleAlert` badge, and its tooltip says what happens: "Claude Code doesn't take images. It gets a link to the file and may open it with its own tools." Nothing else is marked: whether a text file goes with its contents or as a link only shows in its tooltip.
- **Failed**: `CircleAlert` in `--danger` takes the type icon's place and "Can't be read" (or "No longer available") the size's, with the reason in the tooltip. Send stays disabled, its tooltip saying "Remove the attachments that could not be added", so a message never leaves without something the user added.
- **Limits**: past 20, nothing more is added, and the line under the box says "Only 20 attachments fit in one message"; past 10 MB in all, it says "These attachments are over 10 MB in all. Remove some to send." and Send is disabled. With 20 attachments, the menu's two add items are disabled, saying "20 attachments at most".
- **Disabled**: while the agent starts, **+** is disabled with "Wait for Claude Code to start", and the drop overlay says that instead of "Drop to attach" and refuses the drop. While a turn runs or a permission request waits, attaching works and only sending waits.
- A message of attachments alone can be sent.

**Keyboard.** The tab order is the tiles, **+**, the text, then Send. The tiles are one Tab stop: `←` and `→`, `Home` and `End` move between them, `Backspace` or `Delete` removes the focused one and focuses the next, or the text after the last, and `Enter` or `Space` opens it. The `@` popover follows the [IME rule](#composer): no key reaches it during a composition, and an `@` typed through an IME opens it once the composition ends.

**In the thread.** A sent message shows the same tiles without **Remove**, in a row above its bubble and aligned to its end; one of attachments alone has no bubble. They open as in the composer. The thumbnails come with the thread, so a reopened session shows them at once; an image's full size is read when it is opened.

**Elsewhere in the composer.** A [queued](#composer) message carries its attachments, and steering sends them too. [New session](#new-session) has the same ways in, its `@` listing the chosen project's files, and its first message takes them.

**Motion.** A tile enters with a fade and a zoom from 90% over `--duration-base` with `--ease-out-quart`. A removed one fades and shrinks to 90% over `--duration-fast` through Motion's exit, and the tiles after it close the gap with Motion's layout animation. With reduce motion, only the fades remain.

**Accessibility.** The row is a `listbox` named "Attachments"; each tile's name says what it is and how it is sent ("session.ts, sent with its contents"), and the polite live region announces each one added or removed.

## Prompt cache

> Decided 2026-10-24 for [#189](https://github.com/overbench/overbench/issues/189): of four places tried on the [prompt cache canvas](https://claude.ai/artifact/Urm9ZJsmfoHdAKaNFDw9Pt), the control row, the top bar, the thread's end and the sidebar, the maintainer chose the top bar, the control row and the sidebar together, each with a job of its own. For the sidebar, a greyed mark and one status were chosen over a countdown or an hourglass on every row, which read as too heavy.

When a session's [prompt cache](./session-model.md#prompt-cache) expires, its next message reads the whole context again at full price. So the session page says how long the cache has left, and the sidebar tells sessions with a warm cache from cold ones. Three places share the work, so the same time never shows twice on one screen:

| Place                              | Shows                                                      | When                                         |
| ---------------------------------- | ---------------------------------------------------------- | -------------------------------------------- |
| [Top bar](#in-the-top-bar)         | The time left, and a card with the details                 | From the first request on, between turns     |
| [Control row](#in-the-control-row) | The time left, before the usage ring                       | In the last minutes, and once it has expired |
| [Sidebar](#in-the-sidebar)         | A grey mark for a cache that is gone, a ring for one going | Always; the ring only in the last minutes    |

- **The last minutes**: the last five of a cache that lasts an hour, the last one of a shorter cache. They are the time to act, so each place marks them in `--warning`, as a [usage warning](./design-system.md#usage-levels).
- **Nothing to show**: during a turn, since its requests keep the cache in use, and while the cache's lifetime is not known. The sidebar then leaves the row as it is.
- **The time**: over five minutes left, whole minutes, rounded down ("52 min"); in the last five, minutes and seconds ("4:07"). An [estimated](./session-model.md#prompt-cache) lifetime says "about" ("about 4:07"), and "probably" once it is up ("Probably expired").
- **The cost of letting it expire** is the context the next message reads again, the session's `usage.used`, in the compact token format ("about 128k tokens").

### In the top bar

After the title's chevron, a chip: `Hourglass` at 12 px and "Cache 52 min", in 12 px `tabular-nums` `--text-tertiary` on `--bg-subtle`, 24 px high with a 6 px radius and 8 px of padding. In the last minutes the text and the icon turn `--warning`; once the cache has expired the chip reads "Cache expired" in `--text-tertiary` until the next request. The hourglass's sand shows the share of the lifetime left: the top bulb holds what is left, the bottom what has run out. The title truncates before the chip gives way.

A click opens the **cache card**, a `Popover` 320 px wide under the chip:

```text
┌──────────────────────────────────────────────┐
│ Prompt cache             Expires in 52:10    │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━──── │
│ 1-hour cache · last request 7 minutes ago    │
│ If it expires, the next message reads about  │
│ 128k tokens again at full price.             │
└──────────────────────────────────────────────┘
```

- "Prompt cache" and a countdown in minutes and seconds; a 4 px bar of the share left, `--text-tertiary` until the last minutes and `--warning` in them; the lifetime and how long ago the last request was; and the cost of letting it expire, in `--text-secondary`.
- Once expired: "Expired" with no bar, over "The next message reads about 128k tokens again at full price."
- An estimate: "Expires in about 4:07" over "Estimated 5-minute cache · last request …"; once it is up, "Probably expired" over "If it has expired, the next message reads …".
- The [usage popover](#usage-popover) shows the same block after the token totals.

### In the control row

While the cache is warm the usage ring stands alone, since the top bar shows the time. In the last minutes the usage button shows the time before the ring, `Hourglass` at 13 px and "4:07" in `--warning`, so the warning sits where the next message is written; once the cache has expired it shows "Expired" in `--text-tertiary` until the next request. The time slides in as a plan limit in front of the ring does, and the ring keeps its [own states](#composer).

### In the sidebar

- **A cache that is gone**: the row's agent mark turns grey (`grayscale(1)` at 40% opacity) once the session's cache is known to be gone, because it expired or the session has no request on record. A row whose cache is warm, whose lifetime is not known, or that runs keeps its mark in color. A sub-session's mark follows its own cache; a subagent's `Bot` icon stays as it is.
- **A cache about to go**: in the last minutes, the status slot shows the **Prompt cache expiring** ring, between Starting and Unread in [priority](#sidebar).
- The row's accessible name ends with the cache's state ("Prompt cache expires in 4 minutes", "Prompt cache expired", "No prompt cache"), and the row's tooltip adds a line for it after the branch, with the time to the second in the last minutes ("Prompt cache expires in 4:07 · 1-hour cache"). A tooltip on the 14 px mark or the 8 px ring, inside the row's own, would open with it. The tooltip stays in place without content, disabled, so the row is not mounted again, and does not lose focus, as its cache expires. Rows still show no time.

### Clocks

- The sidebar rows and the usage button render only when a state starts: each change is on a timer set for its moment and checked again on each tick of the shared 30 s clock, as for the ring. Inside them, the time before the ring renders each second and the expiring ring's name each minute, both only in the last minutes.
- The top bar's chip renders once a minute while more than five minutes are left, and once a second in the last five. The card and the usage popover count each second only while they are open.

## Git in the top bar

The right side of the top bar shows the project's repository at a glance. Everything comes from the [git service](./git.md#repository-status) and updates as the agent, the terminal or any other tool changes the repository.

```text
⎇ fix/flaky-login  ⇡2 ⇣1  ±3   ⊙ #42 ✓
```

- **Branch**: `GitBranch` and the branch name in monospace, middle-truncated at 200 px. A detached `HEAD` shows the short commit id; an unborn branch shows its name and "no commits".
- **Sync**: `ArrowUp` with the number of commits not pushed, in `--foreground`; `ArrowDown` with the number behind the upstream, in `--muted-foreground`. In sync, nothing shows. A branch with no upstream shows `CloudUpload` and "Not published". While a pull, push or publish runs, a `Spinner` takes the arrows' place.
- **Crowded top bar**: the top bar is a container (`@container/top-bar`), so it adapts to its own width, not the window's. The session title keeps priority at every width: the git status shrinks a thousand times faster (`shrink-1000`), so the branch name truncates first, then the status gives way down to its branch icon, and only then does the title truncate, with its full text in the title button's tooltip. The branch name takes at most a quarter of the bar (`25cqw`), and 96 px below 520 px; "Not published" keeps only its icon below 720 px. The pane toggles always stay.
- **Changes**: `FileDiff` with the number of changed files, staged, unstaged and untracked together. Conflicts replace it with `TriangleAlert` and their count in `--danger`; a merge or rebase in progress adds "Rebasing 2/5" in `--text-secondary`. The branch name and the counts are `--text-secondary`.
- **Pull request**: the current branch's pull request as a chip, `#42` with its state icon and its checks icon. It opens the pull request in the browser; the rest of the cluster opens the branch popover.
- Each part is a ghost button at `--control-height`; the cluster is one Tab stop with arrow-key focus inside. A project that is not a repository, or a machine without `git`, shows nothing here.

| A merge, rebase or conflict in progress | Disabled               | Disabled               | "Finish the rebase first."                                            |

- A disabled button keeps its label and says why in its tooltip; each enabled one's tooltip is the git command it runs, with the same refspec: `git push origin fix:fix`.
- **While it runs** the button keeps its place, swaps its icon for a `Spinner` and its label for "Pulling…", "Pushing…" or "Publishing…" with the seconds so far; the other buttons wait. The top bar's sync arrows give way to the spinner too, so the popover can close.

- **Pushing to the default branch** asks first, whenever the push lands on it, whichever branch is checked out, in an `AlertDialog`: "Push to main?", "2 commits go straight to main, the default branch, without a pull request.", **Cancel** and **Push to main**.
- **Publish…** opens a dialog: the repository name (the folder's name), **Private** or **Public** as a segmented control, the account it goes to, then **Cancel** and **Publish**. It needs `gh`; without it the dialog says how to install or sign in instead.
- **Keyboard**: the popover focuses its first row when it opens. `↑` `↓` move through the rows, `→` or `Enter` expands or opens, `←` folds, `Mod+C` copies the highlighted commit's id (or the branch name), `Esc` closes the card, then the popover.
- **Freshness**: opening the popover refreshes the status and the pull request; while open, the lists it expanded load again when the status changes.

## Files

The Files pane, in the side panel, shows the project's files beside the one that is open, as the reference's Files pane does. The agent host lists, reads and searches them ([project files](./agent-host.md#project-files)); the renderer has no file system access.

```text
┬──────────────────────────────────────────────────────────┐
│ ⌕ Filter, or ? to search in files           ☰   ⤢   ×    │  header, 40 px, a drag region
├──────────────────┬───────────────────────────────────────┤
│ › docs           │ session.ts  src/agent-host     ⧉  ×   │  the open file
│ ⌄ src            │   1  import { randomUUID } from …     │
│   › agent-host   │   2  …                                │  highlighted, line marked
│     index.ts     │                                       │
└──────────────────┴───────────────────────────────────────┘
```

- **Header**: **Hide the file list** (`FolderTree` at 15 px, as the top bar's `Folder` toggle; not `PanelLeft`, which would repeat the sidebar toggle at the window's other side), the filter field, then **Show as a list** / **Show as a tree** (`List`, `ListTree`), **Maximize** and **Close**, as the terminal's header. Maximized with the sidebar collapsed, it starts with the sidebar toggle, as the terminal does.
- **Hiding the list**: to read a file undisturbed, the list folds away and the preview takes the pane's width; the header keeps only **Show the file list**, the same button, **Maximize** and **Close**. Dragging the divider past the list's 160 px minimum folds it too, and dragging it back opens it. The pane's saved layout keeps it folded.
- **Tree**: folders first, then files, by name; folders start closed. Each row shows its [file type icon](./design-system.md#file-icons), a folder's open or closed by its state. Opening a file from the conversation opens its folders and scrolls it into view. Rows are `--row-height` and virtualized, so a project of 50,000 files scrolls like a small one. **Show as a list** lists every path instead.
- **Filter**: typing filters the paths by their characters in order, ignoring case, the best match first (as fzf's first algorithm: consecutive characters, word starts and the file name count for more); the matched characters of the name are marked, the folder follows in `--muted-foreground`. Up to 1,000 matches show, with a count of the rest. `Esc` clears it.
- **Search**: a filter starting with `?` searches the files' text instead (literal, ignoring case, 250 ms after the last keystroke), listing each file with its matching lines, the line number and the match marked; a line opens the file there.
- **Preview**: "Open files appear here" until a file is picked. An open file shows its type icon, name and folder above the text, with **Copy path** and **Close file**. Text shows in CodeMirror 6, loaded on first use: Lezer grammars picked by file name through `@codemirror/language-data` and loaded per language, in GitHub's light and dark colours (`@uiw/codemirror-theme-github`) on the pane's own surface, 13 px on 20 px lines in `--font-mono`, with line numbers and the referenced line marked and centred. Long lines wrap inside the pane; a wrapped line keeps one number, on its first row. The colours are close to Shiki's in the thread, not identical, since the grammars differ ([problem 38](../milestones/m0-feedback.md#38-files-pane-no-markdown-preview-file-type-icons-or-editing)). A Markdown file shows rendered, through the thread's Streamdown in a 50em column, as in the thread, with **Show source** (`Code`) in the header, and **Show preview** (`BookOpen`) back; the choice holds for every Markdown file until changed, and a reference to a line opens the source at it. Images in the file load from the project through the [media scheme](./media.md#the-media-scheme); remote ones stay blocked. Media files come from the same scheme, with no size limit ([media](./media.md)):
  - **Images** (PNG, JPEG, GIF, WebP, AVIF, BMP, ICO) show centred at their own size, fitted to the pane when larger, over `--checker` squares that show their transparency, with a hairline edge, and their pixel size and file size under them ("1920 × 1080 · 66.6 kB"). They zoom and pan in place as the [viewer](#viewer) does, with its gestures and keys, and the header shows **Zoom out** (`Minus`), the zoom level and **Zoom in** (`Plus`).
  - **SVG** shows rendered, as an image, with **Show source** (`Code`) in the header and **Show preview** (`BookOpen`) back, as a Markdown file does; the source opens in the editor, and the preview follows a save.
  - **Video and audio** play centred with Chromium's controls, a video fitted to the pane and an audio player up to 420 px wide, with their size, length and file size under them ("1280 × 720 · 0:04 · 1.1 MB"). Nothing plays by itself.
  - A format Chromium cannot decode, such as HEIC or ProRes, shows an `Empty` saying so, with **Open with default app** (`ExternalLink`).
  - A binary file that is not media, a text file over 1 MB and one that cannot be read show an `Empty` state saying so.
- **No files**: a folder with no files yet, as a new scratch session's, shows one centred `Empty` in the pane's middle (`Folder`, "No files yet"), instead of an empty list beside "Open files appear here"; the header keeps only **Maximize** and **Close**, since there is nothing to filter or hide.
- **Editing**: a text file is edited where it shows, with no separate mode: CodeMirror's `basicSetup` (undo history, search and replace on `Mod+F`, multiple cursors, folding, bracket matching, completion from the file's words) and `Tab` to indent. Search opens as a bar under the header, as the pane's other bars, styled with the pane's tokens; CodeMirror's own words (its buttons, options and screen reader messages) come from the `editor` keys of the `files` catalog, so they follow the interface's language. A Markdown file is edited in its source. A file that is not valid UTF-8 shows read-only, since writing it back would change its bytes. Line endings stay as they were: the editor splits lines only at the file's own line break, the first one it finds or LF, so a stray CR or LF stays part of its line.
- **Unsaved changes**: an edited file shows a 6 px `--foreground` dot after its name and **Save** (`Save`, `Mod+S`) in the header; nothing saves on its own. `Mod+S` saves from anywhere in the open file's part of the pane, and answering a bar puts the focus back in the text. Each project keeps its editor state, undo history included, until it is saved or dropped, so hiding the pane or switching session keeps the edits. Closing the file, or opening another one in the pane from the list, a search or a reference in the thread, first asks in an `AlertDialog`: "Save changes to `name`?" with **Cancel**, **Don't save** and **Save**. Quitting, restarting to update and, on macOS, closing the window ask too ([update notice](#updates)).
- **Saving** sends the text with the version it was read at (`files.write`, [project files](./agent-host.md#project-files)). A failed save keeps the edits and shows the error in a bar under the header.
- **Changes on disk**: without unsaved edits, a reload replaces the editor's text, keeping the cursor and scroll where they still fit. With unsaved edits it does not: if the file changed on disk, a bar under the header says "This file changed on disk." with **Reload**, which drops the edits, and **Keep mine**, after which the next save overwrites the disk. A save of a file that changed since it was read is refused (`conflict`) and shows the same bar, so an agent's edit is never overwritten unseen. A change made outside the app's notice, such as by an editor in another window, shows when the window gains focus or at the latest when you save.
- **Freshness**: the list and the open file reload when the project's git status changes, which follows edits on disk, and when the window gains focus.
- **Diffs**: a file opened from the [branch popover](#branch-popover) shows its change in the preview's place, read-only: the header holds its name, its folder and what it compares ("Uncommitted" or the commit's short id), with **Open file**, which shows the file itself, and **Close diff**, which returns to the file that was open, its unsaved edits untouched. The change shows in the thread's unified diff, highlighted off the main thread; a binary file or one over 1 MB shows an `Empty` saying so. Added 2026-10-22, decided while the maintainer was away; to be reviewed.
- The tree and the preview split the pane with a resize handle; the tree defaults to 220 px.

## Terminal

The built-in [terminal](./terminal.md) opens in the side panel, on the right of the main area. The placement follows the reference; the panel itself follows OverBench's surfaces.

```text
┬───────────────────────────────────┐
│ ▣ zsh  ▣ pnpm dev ●  +       ⤢  × │  header, 40 px, in line with the top bar
│ ~/overbench (fix/flaky-login) $   │
│ pnpm test --filter auth           │
│  ✓ login.test.ts (12)             │
│  ✗ session.test.ts (1)            │
│ ~/overbench (fix/flaky-login) $ █ │
┴───────────────────────────────────┘
```

- **Opening**: `` Ctrl+` `` on every platform, as in VS Code, or the `SquareTerminal` toggle at the right of the top bar, which shows a pressed state while the panel is open. The first time in a project it starts a terminal in the project folder and focuses it; later it shows the terminals that already exist.
- **Panel**: flush with the window's top, right and bottom edges on surface 0 (`--sidebar`), mirroring the sidebar on the left, with no ring, inset or shadow ([terminal tokens](./design-system.md#terminal)). It sits in a `ResizablePanel` with `groupResizeBehavior` `preserve-pixel-size`, so it keeps its width when the window or the sidebar changes: 340 px by default and at least 280 px, while the content beside it never gets less than 360 px. The width is remembered per device. The resize handle shows its grip while hovered or dragged, like the sidebar's. Opening fades the panel in over `--duration-fast` and gives the content its new width at once; closing is immediate.
- **Header**: 40 px (`--top-bar`), so it lines up with the top bar and, on macOS, the traffic lights, and it is part of the window's drag region. On Windows and Linux the panel, not the top bar, reaches the window's right edge, so its header leaves room for the window controls there and the top bar beside it drops its own (`SidePanelContext`).
- **Tabs**: in the header, from its left edge. Each tab is 24 px high with the `SquareTerminal` icon and the title of its foreground process, or the name you gave it; the active tab is raised like a segmented control's thumb (`--segment-thumb` with `shadow-segment`), and a hovered one takes the flat `--bg-hover` fill, so the two never look alike and neither changes the tab's width. A tab is at most 192 px wide; when the header runs short, as it does beside the window controls on Windows and Linux, tabs shrink to 80 px with their titles truncated and their close buttons kept, and only then does the row scroll. A tab that printed while hidden shows a neutral dot, and one whose shell exited shows its exit code. **New terminal** (`+`, `` Ctrl+Shift+` ``) follows the last tab, as in the reference.
- **Renaming and reordering a tab**: double-clicking a tab, or **Rename** in its context menu (with **Close**), turns its label into a field; `Enter` or leaving the field keeps the name, `Esc` cancels, and an empty name returns to the process's title, which a renamed tab keeps in its tooltip. Tabs reorder by dragging (`@dnd-kit/react` sortable, moving by `transform` only), starting after 5 px of travel or a 200 ms hold so a click still selects and a double click still renames; from the keyboard, `Space` picks a focused tab up, the arrow keys move it and `Space` or `Enter` drops it. Names and order live in the renderer for the app's run, since terminals do not survive a restart. On the right: **Maximize** (`Maximize2`) and **Close** (`X`, `` Ctrl+` ``), which hides the panel and keeps the processes running. The header is a window drag region like the top bar, so the tabs and its buttons are `app-region-no-drag`.
- **Maximize** covers the whole main area with the panel, as a layer over the layout, which keeps its sizes underneath, so **Restore** (`Minimize2`) returns to exactly the widths before. The content under it keeps its state but is inert and not rendered (`content-visibility: hidden`). With the sidebar collapsed, the header is then the window's top left corner: it starts with the sidebar toggle and, on macOS, leaves the same room for the traffic lights as the top bar.
- **Closing a tab** ends its shell, after a confirmation if a command is still running.
- **Selection**: selecting text shows a small **Ask Claude Code** button at the end of the selection; it and `Mod+L` put the selection into the composer as a fenced code block. The context menu holds **Copy**, **Paste**, **Select all**, **Clear** and the same **Ask** item.
- **Copy and paste**: `Cmd+C` and `Cmd+V` on macOS; `Ctrl+Shift+C` and `Ctrl+Shift+V` on Windows and Linux, where `Ctrl+C` stays the interrupt.
- **Focus and shortcuts**: while the terminal has focus, keys go to the shell. On macOS, `Cmd` shortcuts still reach the app. On Windows and Linux, only `` Ctrl+` ``, `` Ctrl+Shift+` ``, copy and paste reach the app, since `Ctrl+B`, `Ctrl+L` and `Ctrl+N` mean something to the shell; `Ctrl+L` reaches the app only while text is selected, the way Windows Terminal treats `Ctrl+C`.
- **Projects**: the panel shows the current project's terminals. In a project without one, the open panel shows a quiet empty state with **New terminal**; it never starts a shell by itself when you switch projects.
- **States**: starting (a `Spinner` in the tab while the shell starts), exited (the output stays, with **Restart**), and terminal host stopped (each tab shows "Terminal stopped unexpectedly" with **Restart**).

## Updates

The [updater](./updates.md) works in the background, and the interface shows it only when there is something to do: an update is ready, or it has just been installed. Checking and downloading never show outside Settings.

- **Update notice**: when an update is ready, a row in the sidebar footer, directly above **Settings** and below the sign-in notice when both show. It is a raised row on surface 2 with `--card-ring`, so it reads as an object rather than a warning: the `CircleArrowUp` icon, "Update ready" with the version in `--muted-foreground`, and a small outline **Restart** button. It is neutral, not `--attention`, because nothing waits on it. Hovering it shows "OverBench 0.3.0 is downloaded. Restart to finish; your sessions come back."
- **The dismiss button** is an exception to the sizing and shape rules, accepted by the maintainer: a 16 px round outline `Button` (`icon-xs` with `size-4 rounded-full`, its 12 px icon) on the card's top-right corner, shown on hover and on focus, and always where the pointer cannot hover. It dismisses the notice until a newer version is found. A 24 px control does not fit in the corner, and inline it would cost the words 22 px, which is what made them run under the buttons ([#107](https://github.com/overbench/overbench/issues/107)). It reaches 8 px above and 6 px beside the card, with the card 10 px below the sign-in notice when both show, so its hit area overlaps no other control. It has a tooltip with its name, **Dismiss**.
- The notice is one line. Its words ("Update ready", "Updated to", "is out") hide whole once the label cannot hold them beside the version, so the version and the buttons never truncate, and every notice has a tooltip with its full text.
- In Link mode ([platforms](./updates.md#platforms)) the notice reads "0.3.0 is out" with **Download**, which opens the release page in the browser.
- **After an update**, the same row reads "Updated to 0.3.0" with **What's new**, which opens the release page, and the same ×. It shows for that launch only. There is no dialog and no OS notification.
- With the sidebar collapsed, the sidebar toggle in the top bar carries a small `--foreground` dot, and its tooltip names the version.
- **Restart** with agents working or terminal commands running first opens an `AlertDialog`: "Restart to update?", the running sessions with their agent marks and the busy terminals by command, "Your sessions and drafts come back after the restart.", then **Cancel** and **Restart**. With nothing running it restarts at once. The dialog follows **Ask before quitting while agents or terminal commands are running**.
- Main asks for this dialog, and the same one for quitting, with `app:confirm-quit` (`QuitRequest`, `reason` `update` or `quit`, listing the busy sessions and terminals); the renderer answers with `window.overbench.app.respondQuit(id, confirmed)`. When the page has no listener, or reloads before it answers, main asks with a native dialog instead, so a quit never waits forever.
- **Unsaved files** ([Files](#files)) make the dialog show whatever the setting says, listed under the sessions with their type icons and folders. The buttons become **Cancel**, **Don't save** and **Save and quit** (**Save and restart** for an update); saving waits for every file and stays in the dialog with the error if one fails. On macOS, closing the window with unsaved files asks the same, with `reason` `close` and **Save and close**. The native fallback names the files and offers only **Cancel** and quitting without saving.
- **Settings › About** holds the whole status in one row under the version, the state on the left and its action on the right:

  | State        | Text                                                                                        | Action                       |
  | ------------ | ------------------------------------------------------------------------------------------- | ---------------------------- |
  | Up to date   | "You're up to date" · "Checked 5 minutes ago"                                               | **Check for updates**        |

## Accessibility

- Every control is reachable by keyboard, with a visible focus ring. Lists that act as one control use roving focus.
- An `aria-live="polite"` region announces turn ends and permission requests.
- Icon-only buttons have labels; status is never conveyed by color alone.
- Contrast meets WCAG AA in both themes: every text token reaches 4.5:1 on the surfaces it sits on, which the [contrast check](./testing.md#color-checks) holds; `--text-disabled` is the one exception.

## Performance rules for components

- Entry components are memoized and select only their own entry from the store.
- Streamdown stays in `streaming` mode, so a finished message keeps its rendered blocks. Props it reads through context, such as `controls`, are module constants: a new object per render would re-render every code block and table on each chunk.
- A message longer than 8,000 characters renders in chunks that end on block boundaries (`markdown/chunks.ts`), each a Streamdown of its own inside one `.markdown`: settled chunks never re-render, and only the live tail does, so a streamed update costs the tail instead of the whole message. A text with footnotes or link definitions stays whole, as Streamdown keeps it. Margins collapse through the chunks, so a chunked message is pixel-identical to an unchunked one. On a 200 KB reply, frames while streaming went from 25 to 10 ms at p95 (fake agent, production build, 2026-10-21; [results](../perf/m0.md)).
- Diff highlighting runs in `@pierre/diffs`' worker pool (`WorkerPoolContextProvider`), off the main thread.
- A thread opens on its latest [page](./session-model.md#pages), and the replica holds only the pages loaded. Scrolling back to within a viewport of the top loads the page before, once every loaded item is shown, and again after each prepend while the top is still that close, so a short page fills the view. A spinner shows at the top only when the thread is scrolled all the way up and the page is still on its way, after a beat. Opening a closed session with 1,000 or 4,000 stored entries paints in about 40 ms either way.
- A thread renders from its end: the first frame mounts its last 40 items, and older ones follow in transitions on the next frames, doubling the shown count each time (80, 160, 320, …), which MessageScroller keeps in place as they are prepended. Each prepend lays the thread out again, so doubling keeps the passes logarithmic in the thread's length. Switching to a session with 1,000 entries paints in about 35 ms instead of 260 ms.
- Every `Clamp` (long user messages, long diffs) is measured by one shared `ResizeObserver`, whose callback reads all changed heights while the layout is clean and commits them in one synchronous render before paint, so a clamped block is never painted unclamped first. Measuring in each `Clamp`'s layout effect laid the whole thread out once per commit. Switching back to a cached 4,000-entry session settled in 4.5 s with 28 frames over 50 ms before these two changes, and in 0.9 to 1.0 s with one or two after them (fake agent, production build, 2026-10-21).
- Thread items use `content-visibility: auto` with an intrinsic size estimate, except the last one: while it grows it would flip between skipped and rendered on every chunk, recalculating its whole subtree each time. Its paint containment clips at the item's edge, so items may paint 10 px past it (`overflow-clip-margin`): a fold line or tool row reaches 6 px past the column, and its focus ring 4 px more.
- Micro-interactions and looping indicators are CSS; no component re-renders to animate.
- Markdown, Shiki and the diff renderer are loaded lazily the first time a session needs them; xterm.js and its addons the first time a terminal opens.
- Git status components select only the shown project's status, and pull request chips load their details when they first scroll into view.
