# M0: ACP foundation

> Status: Planned, design drafted · [Architecture](../architecture.md) · [All docs](../README.md)

## Goal

Prove the core architecture end to end: OverBench is a GUI, and it drives Claude Code, Codex and OpenCode over ACP. At the end of M0, a user on macOS, Windows or Linux can open a project, start a session with any of the three agents, and work through real tasks in a thread that streams smoothly, shows every tool call and diff, and asks for permission when the agent does.

M0 is small in scope but not in quality. Everything it ships meets the performance budgets and the UI bar in [AGENTS.md](../../AGENTS.md#core-philosophy-beauty-is-productivity-颜值也是生产力).

## Scope

### In

- **Agent host**: a utility process with port handoff to the renderer, the typed protocol, login shell environment resolution, and agent process supervision with restart. ([design](../design/agent-host.md))
- **Agents**: the three built-in agents, launched and initialized over ACP v1. An Agents page shows each one's status, version and sign-in actions.
- **Projects**: open a folder through the native picker; recent projects in the sidebar.
- **Sessions**: create a session for a project and agent; prompt; stream agent messages, thoughts, tool calls with status and inline diffs, plans and notices; cancel; answer permission requests. ([design](../design/session-model.md))
- **Session controls**: mode, model and reasoning selectors from `configOptions`; slash commands from `available_commands_update`; title from `session_info_update`; context usage from `usage_update`.
- **History**: the session index per project; reopen with `session/load`; recover from an agent crash with `session/resume`; import a project's existing sessions with `session/list`. ([design](../design/persistence.md))
- **Parallel work**: several sessions running at once, each showing in the sidebar whether it is running, waiting for you, or done. Switching between them is instant.
- **Sign-in**: `agent` methods through `authenticate`; `terminal` methods through a copyable command and a retry.
- **Interface**: every screen and state in [the interface design](../design/ui.md), in light and dark themes.
- **All three platforms**: macOS, Windows and Linux are equal targets. CI runs the process tests and packaging on all three.
- **Developer tooling**: the fake agent, Vitest, CI, Export diagnostics, and the performance script. ([design](../design/testing.md))

### Out (planned for later milestones)

- The `fs` and `terminal` client capabilities, the embedded terminal, and in-app terminal sign-in.
- A Changes panel with per-hunk review, checkpoints and undo.
- Git integration and worktrees.
- `@` file mentions and image attachments in the composer.
- MCP server configuration (M0 passes no MCP servers).
- Custom ACP agents and browsing the ACP Registry.
- A managed adapter install that removes the Node.js requirement.
- Elicitation, session fork, steering and prompt queueing.
- A command palette, multiple windows, auto-update, code signing and notarization.

## Acceptance criteria

Each item is checked on macOS, Windows and Linux.

- [ ] Claude Code, Codex and OpenCode each complete a real multi-step task in a sample project, including at least one permission request.
- [ ] Cancelling mid-turn stops the agent, answers pending permission requests with `cancelled`, and leaves the session usable.
- [ ] Killing an agent process marks its sessions disconnected; they resume without losing the visible thread.
- [ ] Killing the agent host does not close the window, sessions reconnect, and no agent process is left running.
- [ ] Quitting the app leaves no agent process running.
- [ ] Reloading the window restores every open session from snapshots.
- [ ] A signed-out agent shows its sign-in methods, and signing in lets the session continue.
- [ ] Launched from the Dock, Start menu or a desktop launcher, the app finds Node.js and the agents.
- [ ] Three sessions stream at the same time without dropped frames.
- [ ] Every screen is checked in light and dark themes and with reduce-motion on.
- [ ] `pnpm format:check`, `pnpm lint`, `pnpm typecheck` and `pnpm test` pass, and CI is green on all three platforms.

## Performance budgets

Measured on a production build with the fake agent as the load, as described in [testing](../design/testing.md#measuring-performance), on an Apple Silicon Mac, a Windows 11 x64 machine and an Ubuntu LTS x64 machine.

| Metric                                                         | Budget                |
| -------------------------------------------------------------- | --------------------- |
| App launch to first interactive frame, excluding agent startup | under 500 ms          |
| Renderer commits while streaming                               | at most one per frame |
| Main-thread long tasks while streaming 200 updates per second  | none over 50 ms       |
| Switching to a session with 1,000 entries, to first paint      | under 100 ms          |
| Keystroke to paint in the composer                             | under 16 ms           |
| Agent host memory, excluding agent processes                   | under 150 MB          |

## Dependencies

Approved by the maintainer on 2026-10-20. Each is installed by the work package that first uses it. All are bundled, by Vite into the renderer or by electron-vite into the agent host, so they go in `devDependencies`.

| Package                    | Purpose                             | Used from | Why this one                                                                                      |
| -------------------------- | ----------------------------------- | --------- | ------------------------------------------------------------------------------------------------- |
| `@agentclientprotocol/sdk` | ACP client                          | M0.1      | The official SDK; stable v1 by default, with v2 behind an explicit import                         |
| `vitest`                   | Unit, integration and process tests | M0.1      | Shares the Vite pipeline the project already uses                                                 |
| `streamdown`               | Markdown in agent messages          | M0.3      | Built for streaming: renders incomplete markdown mid-stream, and sanitizes its output             |
| `shiki`                    | Syntax highlighting                 | M0.3      | What the shadcn `code-block` component, Streamdown's code plugin and `@pierre/diffs` all build on |
| `@pierre/diffs`            | Diffs in tool calls                 | M0.3      | Shiki-based split and unified diffs with a worker pool and polished defaults                      |

Streamdown's own plugins `@streamdown/code` (Shiki highlighting) and `@streamdown/cjk` (Chinese, Japanese and Korean text) are part of the Streamdown choice.

## Decisions

| Question  | Decision                                                                                                                 |
| --------- | ------------------------------------------------------------------------------------------------------------------------ |
| Platforms | macOS, Windows and Linux are equal targets in M0. Platform differences are designed in the agent host and checked by CI. |
| OpenCode  | Use the user's installed `opencode`, with an optional binary override; no OverBench-managed download in M0.              |
| Node.js   | M0 requires Node.js 22 or later for the Claude Code and Codex adapters, and the Agents page says so when it is missing.  |

## Risks

| Risk                                                           | Mitigation                                                                                                           |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| ACP v2 changes the shape of updates                            | ACP types stay inside `src/agent-host/acp/`; v2 is a second mapper onto the same session model                       |
| Agents differ in permission options, modes and update patterns | The UI is driven by advertised capabilities and data, with no agent-specific branches outside the catalog and mapper |
| Adapter updates change behavior                                | Versions are pinned and bumped only after a pass with the fake agent and the real agent                              |
| Process handling differs across platforms                      | One documented rule per platform in the agent host design, and process tests on all three platforms in CI            |
| `npx` first run is slow or offline                             | A visible starting state with progress, the npm cache afterwards, and the managed install later                      |
| Large tool outputs or long replays slow the UI                 | Coalesced patches, watched-only streaming, normalized state, `content-visibility`, and virtualization if measured    |
