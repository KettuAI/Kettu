# M0: ACP foundation

> Status: Implemented, in acceptance · [Architecture](../architecture.md) · [All docs](../README.md)

## Goal

Prove the core architecture end to end: OverBench is a GUI, and it drives Claude Code, Codex and OpenCode over ACP. At the end of M0, a user on macOS, Windows or Linux can open a project, start a session with any of the three agents, and work through real tasks in a thread that streams smoothly, shows every tool call and diff, and asks for permission when the agent does.

M0 is small in scope but not in quality. Everything it ships meets the performance budgets and the UI bar in [AGENTS.md](../../AGENTS.md#core-philosophy-beauty-is-productivity-颜值也是生产力).

## Scope

### In

- **Agent host**: a utility process with port handoff to the renderer, the typed protocol, login shell environment resolution, and agent process supervision with restart. ([design](../design/agent-host.md))
- **Agents**: the three built-in agents, launched and initialized over ACP v1. Settings › Agents shows each one's status, version and sign-in actions.
- **Settings**: one page with General, Appearance, Agents, Notifications, Keyboard shortcuts, Advanced and About; changes apply at once and are kept in `settings.json`. ([design](../design/persistence.md#settings))
- **Projects**: open a folder through the native picker; recent projects in the sidebar.
- **Sessions**: create a session for a project and agent; prompt; stream agent messages, thoughts, tool calls with status and inline diffs, plans and notices; cancel; answer permission requests. ([design](../design/session-model.md))
- **Session controls**: mode, model and reasoning selectors from `configOptions`; slash commands from `available_commands_update`; title from `session_info_update`; context usage from `usage_update` and token totals from the prompt response; the account and its plan limits where the adapter reports them (Claude Code today). ([design](../design/session-model.md#plan-limits))
- **Git**: the branch, sync state, working tree changes and an in-progress operation in the top bar; the branch popover with the branch lane and commits; commits, pushes and branch switches in the thread; pull requests through the GitHub CLI as chips, sidebar badges and the current branch's state. Read-only, apart from Fetch. ([design](../design/git.md))
- **Terminal**: a built-in terminal at the bottom of the main area, per project, with tabs, the user's login shell, and sending a selection to the composer. ([design](../design/terminal.md))
- **History**: the session index per project; reopen with `session/load`; recover from an agent crash with `session/resume`; import a project's existing sessions with `session/list`. ([design](../design/persistence.md))
- **Sub-sessions**: subagents an agent starts, through the ACP subagents RFD where the adapter supports it (Claude Code and Codex), and sub-sessions the user starts under a session; both show as a tree under their parent in the sidebar. ([design](../design/session-model.md#sub-sessions))
- **Parallel work**: several sessions running at once, each showing in the sidebar whether it is running, waiting for you, or done. Switching between them is instant.
- **Sign-in**: `agent` methods through `authenticate`; `terminal` methods in the built-in terminal, or through a copyable command and a retry.
- **Interface**: every screen and state in [the interface design](../design/ui.md), in light and dark themes, built on the [design system](../design/design-system.md) tokens.
- **All three platforms**: macOS, Windows and Linux are equal targets. CI runs the process tests and packaging on all three.
- **Updates**: checking GitHub Releases in the background, downloading, and installing on restart on Windows and Linux; macOS builds link to the release page until they are signed. ([design](../design/updates.md))
- **Developer tooling**: the fake agent, Vitest, CI, Export diagnostics, and the performance script. ([design](../design/testing.md))

### Out (planned for later milestones)

- The `fs` and `terminal` client capabilities, so agents do not run commands in OverBench's terminals.
- Terminals that survive a restart, split terminals and search in the terminal.
- A Changes panel with per-hunk review, checkpoints and undo.
- Git actions in the interface (staging, committing, pushing, creating pull requests from a form), worktrees, and hosts other than GitHub for pull requests.
- `@` file mentions and image attachments in the composer.
- MCP server configuration (M0 passes no MCP servers).
- Custom ACP agents and browsing the ACP Registry.
- A managed adapter install that removes the Node.js requirement.
- Elicitation, session fork, steering and prompt queueing.
- A command palette, multiple windows, code signing and notarization, and a beta update channel.
- The comfortable density, pinned sessions with drag reordering, and in-app sound cues.
- A launch mark, once the OverBench logo is final ([launch](../design/ui.md#launch)).

## Progress

As of 2026-10-21, all five work packages are implemented on `main`, and the acceptance criteria below wait for the maintainer's acceptance.

- **macOS**: the interface was checked against the fake agent's scenarios, in light and dark themes, with reduce motion on and at the minimum window size. The budgets were measured ([results](../perf/m0.md)); all but the keystroke budget are met. Claude Code, Codex and OpenCode start, initialize and answer `session/list`; real tasks with them are part of the acceptance.
- **Windows and Linux**: CI runs formatting, lint, type checks, tests, the build and packaging on each. The interface and the budgets have not been checked by hand there yet.

## Acceptance criteria

Each item is checked on macOS, Windows and Linux.

- [ ] Claude Code, Codex and OpenCode each complete a real multi-step task in a sample project, including at least one permission request.
- [ ] Cancelling mid-turn stops the agent, answers pending permission requests with `cancelled`, and leaves the session usable.
- [ ] Killing an agent process marks its sessions disconnected; they resume without losing the visible thread.
- [ ] Killing the agent host does not close the window, sessions reconnect, and no agent process is left running.
- [ ] Quitting the app leaves no agent process running.
- [ ] Reloading the window restores every open session from snapshots.
- [ ] A signed-out agent shows its sign-in methods, and signing in lets the session continue.
- [ ] A subagent started by Claude Code or Codex shows under its parent, and its permission requests reach the user.
- [ ] A changed setting applies at once and survives a restart.
- [ ] Launched from the Dock, Start menu or a desktop launcher, the app finds Node.js and the agents.
- [ ] Three sessions stream at the same time without dropped frames.
- [ ] After an agent commits and pushes, the thread shows both events, the top bar shows the branch in sync, and the pull request chip shows its checks.
- [ ] `yes | head -c 50000000` in the terminal leaves the thread and the composer responsive, and the terminal keeps up without growing memory.
- [ ] An installed build finds a newer published release, downloads it and restarts into it on Windows and Linux, and links to it on macOS; after the restart the open session and drafts are back.
- [ ] A Claude Code session on a subscription shows its 5-hour and weekly limits once Claude Code reports them.
- [ ] Every screen is checked in light and dark themes and with reduce-motion on.
- [ ] `pnpm format:check`, `pnpm lint`, `pnpm typecheck` and `pnpm test` pass, and CI is green on all three platforms.

## Performance budgets

Measured on a production build with the fake agent as the load, as described in [testing](../design/testing.md#measuring-performance), on an Apple Silicon Mac, a Windows 11 x64 machine and an Ubuntu LTS x64 machine.

| Metric                                                         | Budget                |
| -------------------------------------------------------------- | --------------------- |
| App launch to first interactive frame, excluding agent startup | under 500 ms          |
| Renderer commits while streaming                               | at most one per frame |
| Main-thread long tasks while streaming 200 updates per second  | none over 50 ms       |
| Switching to a session with 1,000 entries, to first paint      | under 100 ms          |
| Keystroke to paint in the composer                             | under 16 ms           |
| Agent host memory, excluding agent processes                   | under 150 MB          |

## Dependencies

Approved by the maintainer on 2026-10-20. Each is installed by the work package that first uses it. All but `node-pty` and `electron-updater` are bundled, by Vite into the renderer or by electron-vite into the agent host, so they go in `devDependencies`. Those two are loaded at runtime, so they go in `dependencies`: `node-pty` is a native module that the terminal host loads and is unpacked from the asar archive, and `electron-updater` is loaded by main.

## Decisions

| Question         | Decision                                                                                                                                                                                                                                                                                                                                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Platforms        | macOS, Windows and Linux are equal targets in M0. Platform differences are designed in the agent host and checked by CI.                                                                                                                                                                                                                                                                                          |
| OpenCode         | Use the user's installed `opencode`, with an optional binary override; no OverBench-managed download in M0.                                                                                                                                                                                                                                                                                                       |
| Node.js          | M0 requires Node.js 22 or later for the Claude Code and Codex adapters, and Settings › Agents and the Welcome screen say so when it is missing.                                                                                                                                                                                                                                                                   |
| Visual benchmark | The first version benchmarks Claude Desktop through the open-claude-ui analysis: its principles and measurements, never its brand assets or reconstructed code ([design system](../design/design-system.md#design-reference)).                                                                                                                                                                                    |
| Subagents        | Shown as child sessions through the ACP subagents RFD, the one unstable part of ACP that M0 uses ([architecture](../architecture.md#protocol-version)). OpenCode does not implement it, so its subagents stay tool calls in the parent thread.                                                                                                                                                                    |
| Terminal         | At the bottom of the main area, where developers expect it, leaving the right side to the Changes panel; per project; xterm.js and `node-pty` in a terminal host of its own ([terminal](../design/terminal.md)).                                                                                                                                                                                                  |
| Git              | Read-only status plus Fetch; pull requests through the user's `gh`, so OverBench holds no GitHub credential ([git](../design/git.md)).                                                                                                                                                                                                                                                                            |
| Plan limits      | Shown where the adapter reports them: Claude Code now; Codex once `codex-acp` forwards the limits it already receives ([plan limits](../design/session-model.md#plan-limits)).                                                                                                                                                                                                                                    |
| Updates          | Background download and install on restart, through `electron-updater` and GitHub Releases; a quiet notice in the sidebar footer once an update is ready, never a dialog or OS notification ([updates](../design/updates.md), [interface](../design/ui.md#updates)); chosen over a top bar control, a badge on Settings and a floating card. Unsigned macOS builds link to the download until code signing lands. |
| Density          | Compact only; the comfortable values are recorded for a later setting.                                                                                                                                                                                                                                                                                                                                            |

## Risks

| Risk                                                           | Mitigation                                                                                                                                |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| ACP v2 changes the shape of updates                            | ACP types stay inside `src/agent-host/acp/`; v2 is a second mapper onto the same session model                                            |
| Agents differ in permission options, modes and update patterns | The UI is driven by advertised capabilities and data, with no agent-specific branches outside the catalog and mapper                      |
| Adapter updates change behavior                                | Versions are pinned and bumped only after a pass with the fake agent and the real agent                                                   |
| Process handling differs across platforms                      | One documented rule per platform in the agent host design, and process tests on all three platforms in CI                                 |
| The subagents RFD changes before it is stable                  | Only the mapper reads it; without it, subagents fall back to tool calls in the parent thread, as OpenCode's are                           |
| `node-pty` fails to build or load on a platform                | It loads only in the terminal host, so a failure disables the terminal and nothing else; CI packages and starts it on all three platforms |
| Large repositories make `git status` slow                      | One run per repository at a time, coalesced triggers, a 10 s timeout, and the last value shown meanwhile                                  |
| `npx` first run is slow or offline                             | A visible starting state with progress, the npm cache afterwards, and the managed install later                                           |
| Large tool outputs or long replays slow the UI                 | Coalesced patches, watched-only streaming, normalized state, `content-visibility`, and virtualization if measured                         |
