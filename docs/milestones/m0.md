# M0: ACP foundation

> Status: planned. Architecture: [docs/architecture.md](../architecture.md).

## Goal

Prove the core architecture end to end: OverBench is a GUI, and it drives Claude Code, Codex and OpenCode over ACP. At the end of M0, a user can open a project, start a session with any of the three agents, and work through real tasks in a thread that streams smoothly, shows every tool call and diff, and asks for permission when the agent does.

M0 is small in scope but not in quality. Everything it ships meets the performance budgets and the UI bar in [AGENTS.md](../../AGENTS.md#core-philosophy-beauty-is-productivity-颜值也是生产力).

## Scope

### In

- **Agent host**: a utility process with port handoff to the renderer, the typed RPC contract, login shell environment resolution, and agent process supervision with restart.
- **Agents**: the three built-in agents, launched and initialized over ACP v1. An Agents page shows each one's status (not found, preparing, ready, needs sign-in, error), version and sign-in actions.
- **Projects**: open a folder through the native picker; recent projects in the sidebar.
- **Sessions**: create a session for a project and agent; prompt; stream agent messages, thoughts, tool calls with status and inline diffs, plans and notices; cancel; answer permission requests.
- **Session controls**: mode, model and reasoning selectors from `configOptions`; slash commands from `available_commands_update`; title from `session_info_update`; context usage meter from `usage_update`.
- **History**: the session index per project; reopen with `session/load`; recover from an agent crash with `session/resume`; import a project's existing sessions with `session/list`.
- **Parallel work**: several sessions running at once, each showing in the sidebar whether it is running, waiting for you, or done. Switching between them is instant.
- **Sign-in**: `agent` methods through `authenticate`; `terminal` methods through a copyable command and a retry.
- **Developer tooling**: `tools/fake-agent` for scripted turns, and Export diagnostics with the in-memory ACP traffic log and agent stderr.

### Out (planned for later milestones)

- The `fs` and `terminal` client capabilities, the embedded terminal, and in-app terminal sign-in.
- A Changes panel with per-hunk review, checkpoints and undo.
- Git integration and worktrees.
- `@` file mentions and image attachments in the composer.
- MCP server configuration (M0 passes no MCP servers).
- Custom ACP agents and browsing the ACP Registry.
- A managed adapter install that removes the Node.js requirement.
- Elicitation, session fork, steering and prompt queueing.
- Multiple windows, auto-update, code signing and notarization.

## Acceptance criteria

- [ ] Claude Code, Codex and OpenCode each complete a real multi-step task in a sample project, including at least one permission request.
- [ ] Cancelling mid-turn stops the agent, answers pending permission requests with `cancelled`, and leaves the session usable.
- [ ] Killing an agent process marks its sessions disconnected; the next action resumes them without losing the visible thread.
- [ ] Killing the agent host does not close the window; sessions reconnect.
- [ ] Reloading the window restores every open session from snapshots.
- [ ] A signed-out agent shows its sign-in methods, and signing in lets the session continue.
- [ ] Three sessions stream at the same time without dropped frames.
- [ ] Every screen is checked in light and dark themes and with reduce-motion on.
- [ ] `pnpm format:check`, `pnpm lint`, `pnpm typecheck` and the unit tests pass.

## Performance budgets

Measured on an Apple Silicon Mac with a production build, using the fake agent as the load.

| Metric                                                         | Budget                |
| -------------------------------------------------------------- | --------------------- |
| App launch to first interactive frame, excluding agent startup | under 500 ms          |
| Renderer commits while streaming                               | at most one per frame |
| Main-thread long tasks while streaming 200 updates per second  | none over 50 ms       |
| Switching to a session with 1,000 entries, to first paint      | under 100 ms          |
| Keystroke to paint in the composer                             | under 16 ms           |
| Agent host memory, excluding agent processes                   | under 150 MB          |

## Dependencies pending approval

M0 needs libraries for concerns the UI stack does not cover yet. None is installed until the maintainer approves it.

| Package                    | Purpose                               | Why this one                                                                          | Alternative              |
| -------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------ |
| `@agentclientprotocol/sdk` | ACP client (required)                 | The official SDK; stable v1 by default, with v2 available behind an explicit import   | Hand-rolled JSON-RPC     |
| `streamdown`               | Markdown in agent messages            | Built for streaming: renders incomplete markdown mid-stream, and sanitizes its output | `react-markdown`         |
| `shiki`                    | Syntax highlighting                   | Already what the shadcn `code-block` component uses, and the base of `@pierre/diffs`  | –                        |
| `@pierre/diffs`            | Diff rendering in tool calls          | Shiki-based split and unified diffs with polished defaults                            | `diff` plus our own view |
| `vitest`                   | Unit tests for the mapper and reducer | Shares the Vite pipeline the project already uses                                     | `node:test`              |

All of them are renderer-bundled or bundled into the agent host, so they go in `devDependencies`.

## Open questions

1. **Platforms.** Proposed: M0 is verified on macOS; Windows and Linux must build and launch, with full verification in M1.
2. **OpenCode distribution.** Proposed: use the user's installed `opencode`. The alternative is downloading the registry's binary, which lags behind releases.
3. **Node.js requirement.** Proposed: M0 requires Node.js 22 or later for the Claude Code and Codex adapters and says so on the Agents page; the managed install removes it later.

## Risks

| Risk                                                           | Mitigation                                                                                                           |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| ACP v2 changes the shape of updates                            | ACP types stay inside `src/agent-host/acp/`; v2 is a second mapper onto the same thread model                        |
| Agents differ in permission options, modes and update patterns | The UI is driven by advertised capabilities and data, with no agent-specific branches outside the catalog and mapper |
| Adapter updates change behavior                                | Versions are pinned and bumped only after a pass with the fake agent and the real agent                              |
| `npx` first run is slow or offline                             | A visible preparing state with progress, the npm cache afterwards, and the managed install later                     |
| Large tool outputs or long replays slow the UI                 | Frame-coalesced patches, normalized state, `content-visibility`, and virtualization if measured                      |
